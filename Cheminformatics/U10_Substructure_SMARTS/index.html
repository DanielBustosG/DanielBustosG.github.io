Searching a database of molecules for the ones that contain a particular arrangement of atoms is the oldest and still one of the most used operations in cheminformatics. It is how a medicinal chemist pulls every sulfonamide out of a million-compound library, how a screening centre flags the compounds likely to misbehave in an assay, and how a property model is told "this molecule has a nitro group". The query language that makes it precise is SMARTS. This unit teaches SMARTS the way a programmer learns a regular-expression dialect: a grammar of atom and bond primitives, logical operators with a defined precedence, and a matching engine with a known cost. The slides give you the map; this notebook is the territory you can run and modify.

Learning objectives

  • Explain precisely what distinguishes a SMILES (a specific molecule) from a SMARTS (a pattern that matches a set of molecules), and why the distinction matters in code.

  • Write and test SMARTS for real functional groups — amide, sulfonamide, nitro and the Michael acceptor — and use recursive SMARTS to express atomic environments.
  • Screen a compound library by substructure, build a structural-alert catalogue (PAINS-style), highlight the matched atoms on the drawing, and discuss what such alerts can and cannot tell you.

1. A molecule versus a query: SMILES is not SMARTS

Unit 3 taught SMILES (Simplified Molecular-Input Line-Entry System): a compact text serialisation of one concrete molecule,[1] with a canonical form that makes the string a unique key for that molecule.[14] The string CC(=O)O is acetic acid — a definite graph with definite atoms. SMARTS (SMiles ARbitrary Target Specification)[2] looks superficially similar but means something entirely different: it is a pattern that describes a set of molecules (or, more precisely, a set of atom-and-bond arrangements), and its job is to answer the question "does this molecule contain something that looks like this?".

Chemistry box — substructure, functional group, scaffold

A substructure is any connected piece of a molecule: a few atoms and the bonds between them. A functional group is a small substructure with characteristic chemistry — a carboxylic acid (−COOH), an amine (−NH₂), a nitro group (−NO₂) — that behaves roughly the same wherever it appears (Unit 1). A scaffold is the larger core ring system a series of molecules shares (Unit 11). Asking "which molecules contain group X?" is a substructure search, and SMARTS is how X is written down.

The cleanest way for a programmer to hold the distinction is by analogy to text:

  • A SMILES is a literal string — "cat". It denotes one exact thing.
  • A SMARTS is a regular expression — [cC]a. — a pattern with wildcards, character classes and logic that matches many strings.

The analogy is exact in spirit: SMARTS adds, on top of the SMILES atom/bond syntax, query primitives (wildcards like "any aromatic atom", "any ring bond") and logical operators (and, or, not). The parser that reads them is different, too: Chem.MolFromSmiles builds a molecule; Chem.MolFromSmarts builds a query molecule whose atoms and bonds carry constraints rather than fixed values. Confusing the two is the single most common SMARTS bug, so we start by making it concrete.

# The SAME text parsed two ways gives two different kinds of object.
smi_obj   = Chem.MolFromSmiles("C=O")     # a molecule: formaldehyde (one carbon, one oxygen, a double bond)
smarts_obj = Chem.MolFromSmarts("C=O")    # a query: "an aliphatic carbon double-bonded to an oxygen"
print("MolFromSmiles -> ", type(smi_obj).__name__, "| formula", rdMolDescriptors.CalcMolFormula(smi_obj))
print("MolFromSmarts ->", type(smarts_obj).__name__, "| a query has no fixed formula")

# A query is used to interrogate real molecules. Does each drug contain a C=O?
library = {"acetone": "CC(=O)C", "ethanol": "CCO", "acetic acid": "CC(=O)O",
           "benzene": "c1ccccc1", "acetamide": "CC(=O)N", "aspirin": "CC(=O)Oc1ccccc1C(=O)O"}
for name, smi in library.items():
    m = Chem.MolFromSmiles(smi)
    print(f"  {name:12s} contains C=O ? {m.HasSubstructMatch(smarts_obj)}")

The printout makes the point: C=O read as SMILES is the molecule formaldehyde, but read as SMARTS it is a carbonyl query that matches acetone, acetic acid, acetamide and aspirin (each has a C=O) while rejecting ethanol and benzene (which have none). One pattern, many molecules — the defining behaviour of a query.

The number-one SMARTS mistake

Passing a SMARTS string to MolFromSmiles (or a SMILES to MolFromSmarts and expecting it to behave as a molecule) silently gives the wrong object. The parsers overlap — C=O is valid in both — so you get no error, just wrong results. Rule: a query always comes from Chem.MolFromSmarts; a molecule to be searched always comes from Chem.MolFromSmiles (or a file). Every target molecule should also be sanitised (RDKit does this by default) so its aromaticity and valence are perceived before you match against it.

2. Substructure matching is subgraph isomorphism

Unit 1 established the central translation: a molecule is a labelled graph — atoms are nodes labelled with their element (and charge, aromaticity, …), bonds are edges labelled with their order. A SMARTS query is also a labelled graph, except its labels are constraints ("a node that is a carbon with three connections") rather than fixed values. "Does molecule M contain pattern Q?" is therefore the question: is the query graph Q isomorphic to some subgraph of the molecule graph M, respecting all the labels? This is the classic subgraph-isomorphism problem of computer science.

Key idea — the cost of substructure search

Subgraph isomorphism is NP-complete in general: there is no known algorithm that solves every instance in time polynomial in the graph size. Yet substructure search over millions of molecules is routine and fast. Three things rescue it: (1) molecular graphs are tiny (tens of atoms) and sparse (valence caps every degree at ~4, Unit 1); (2) the element/charge/aromaticity labels prune the search enormously — a query carbon can only map to molecule carbons; (3) real systems screen out most molecules with a cheap pre-filter (a fingerprint screen, Unit 5[16], often using substructure-key fingerprints such as the MACCS keys, which are themselves a list of SMARTS patterns[18]) before running the exact match on the few survivors; the standard textbook account of substructure searching and screening is Leach and Gillet.[26] The exact matcher itself is a backtracking search: the classic algorithms are Ullmann's[3] and the faster VF2,[4] which RDKit[15] uses; the broader family of (sub)graph-isomorphism methods and their chemical applications is surveyed by Ehrlich and Rarey.[17]

RDKit exposes the matcher through three methods on a molecule, each taking a query:

  • mol.HasSubstructMatch(query) → bool: is there at least one match? (the cheap existence test used in filtering).
  • mol.GetSubstructMatch(query) → a tuple of molecule atom indices for one match (empty if none).
  • mol.GetSubstructMatches(query) → a tuple of tuples, all distinct matches.

The returned tuples are the heart of it: position i of a match tuple is the molecule-atom index that the i-th query atom mapped onto. That mapping is exactly the isomorphism, and it is what lets us highlight the matched part of the drawing later. The next cell runs all three on a molecule with more than one carbonyl.

# The three matching methods, and what the returned atom-index tuples mean.
aspirin = Chem.MolFromSmiles("CC(=O)Oc1ccccc1C(=O)O")
carbonyl = Chem.MolFromSmarts("[#6]=[#8]")              # any carbon double-bonded to any oxygen
print("HasSubstructMatch :", aspirin.HasSubstructMatch(carbonyl))
print("GetSubstructMatch  :", aspirin.GetSubstructMatch(carbonyl), "  (one match: query atom 0 -> mol atom, query atom 1 -> mol atom)")
matches = aspirin.GetSubstructMatches(carbonyl)
print("GetSubstructMatches:", matches, f"  ({len(matches)} carbonyls found)")
# Decode the first match: which molecule atoms (elements) did the two query atoms land on?
for qi, mi in enumerate(matches[0]):
    a = aspirin.GetAtomWithIdx(mi)
    print(f"   query atom {qi}  ->  mol atom {mi} ({a.GetSymbol()})")

3. SMARTS atom primitives — the node constraints

A SMARTS atom is written either as an organic-subset symbol (C, N, o, c, …) exactly as in SMILES, or — and this is where the query power lives — inside square brackets as a conjunction of primitives. Each primitive constrains one property of the atom the query node may map onto. For a computer scientist they are field predicates on a node: "element == 6 AND total-connections == 3 AND ring-member". The essential primitives are few; the table below lists the ones that cover almost all practical SMARTS.

Chemistry box — aromatic vs aliphatic, and "degree"

Aromatic atoms belong to a flat, electron-delocalised ring such as benzene (Unit 1); SMARTS writes them lowercase (c, n, o) and non-aromatic ("aliphatic") atoms uppercase (C, N, O). An atom's degree is how many neighbours it has. SMARTS distinguishes two counts you must not confuse: D is the number of explicit (heavy-atom) connections, while X is the total connection count including hydrogens. A carbonyl carbon in acetone has D3 (bonded to two carbons and one oxygen) and also X3 (no hydrogens); a methyl carbon has D1 but X4 (one carbon plus three hydrogens).

4. SMARTS bond primitives — the edge constraints

Bonds between SMARTS atoms carry their own predicates. The defaults are the familiar SMILES bond symbols, plus a few query-only wildcards.

# Bond primitives, demonstrated by counting matches in molecules that do/don't contain each.
bonds = pd.DataFrame([
    ("-",  "single bond",                 "[#6]-[#6]"),
    ("=",  "double bond",                 "[#6]=[#6]"),
    ("#",  "triple bond",                 "[#6]#[#6]"),

    ("!@", "non-ring (acyclic) bond",     "[#6]!@[#6]"),

The counts confirm each bond predicate: = finds the double bond of propene but nothing in benzene (whose bonds are aromatic, matched only by : or the wildcard ~); # finds the triple bond of propyne; @ finds the ring bonds of benzene and cyclohexane but none in the acyclic molecules; and !@ (non-ring) finds the acyclic C–C bonds everywhere except inside the rings. Two lessons for writing robust SMARTS: first, an aromatic C=C is not matched by C=C — aromatic bonds need : or the atomic-number/aromatic form, a frequent bug; second, the ~ ("any bond") and @/!@ (ring/acyclic) wildcards let a pattern be deliberately loose about bond order while staying strict about topology, which is exactly what reactive-group and scaffold queries need.

Chemistry box — why "ring vs chain" is a chemical distinction

Whether a bond or atom sits in a ring changes its chemistry: ring atoms are held rigid, ring bonds cannot rotate freely, and a group fused into an aromatic ring behaves differently from the same group dangling on a chain. That is why SMARTS gives ring membership (@, R, r) first-class status — many alerts and functional-group definitions hinge on "…but only when it is (not) in a ring".

5. Logical operators and precedence — the programmer's heart of SMARTS

This is the section where SMARTS becomes a real query language rather than a notation. Inside a bracket atom (and between bonds) you combine primitives with four logical operators, and — exactly as in a programming language — they have a fixed precedence that you must know or your queries will quietly mean the wrong thing.

Key idea — the four operators and their precedence

From highest binding to lowest:

  1. ! — NOT (unary): [!#6] = not carbon.
  2. & — high-precedence AND: [C&H1] = carbon and one H. Writing two primitives next to each other with no symbol ([CH1]) is an implicit &.
  3. , — OR: [C,N] = carbon or nitrogen.
  4. ; — low-precedence AND: binds looser than ,.

So & binds tighter than ,, which binds tighter than ;. The whole purpose of having two ANDs (& and ;) is to straddle the OR: [C,N;H1] parses as (C OR N) AND H1, whereas [C,NH1] parses as C OR (N AND H1). Same characters, different meaning — the classic SMARTS trap.

The next cell demonstrates the trap on real molecules so you never fall into it. It compares two patterns that differ only in whether the AND is the tight &/implicit form or the loose ; form.

# Precedence trap: (N or O) AND one-H   vs   N OR (O AND one-H).
pat_loose = Chem.MolFromSmarts("[#7,#8;H1]")   # ; is low-precedence AND: (N or O) that has exactly 1 H
pat_tight = Chem.MolFromSmarts("[#7,#8H1]")    # implicit & is high: N(any H)  OR  (O with 1 H)
probe = {"methanol CO": "CO", "dimethyl ether COC": "COC", "methylamine CN": "CN",
         "trimethylamine": "CN(C)C", "acetamide CC(=O)N": "CC(=O)N"}
rows = []
for name, smi in probe.items():
    m = Chem.MolFromSmiles(smi)
    rows.append((name, len(m.GetSubstructMatches(pat_loose)), len(m.GetSubstructMatches(pat_tight))))
df = pd.DataFrame(rows, columns=["molecule", "[#7,#8;H1]  (N|O) & 1H", "[#7,#8H1]  N | (O&1H)"])
print(df.to_string(index=False))

          molecule  [#7,#8;H1]  (N|O) & 1H  [#7,#8H1]  N | (O&1H)
       methanol CO                       1                      1
dimethyl ether COC                       0                      0
    methylamine CN                       0                      1
    trimethylamine                       0                      1
 acetamide CC(=O)N                       0                      1

Read the two columns across the rows and the precedence rule becomes concrete. For methylamine (CN, nitrogen bearing two hydrogens) the loose pattern (N or O) AND exactly-1-H does not match (the nitrogen has 2 H), but the tight pattern N OR (O with 1 H) matches the nitrogen regardless of its hydrogen count. For dimethyl ether (COC, oxygen with no H) neither matches. For methanol (CO, oxygen with one H) both match. The two columns disagree precisely where the OR and the AND fight over an atom — which is exactly where a mis-remembered precedence silently corrupts a filter. When in doubt, be explicit: write ; to force "apply this constraint to whatever the OR produced", and test your SMARTS on a handful of molecules whose answer you know — as we just did.

Write SMARTS defensively

Three habits prevent most SMARTS bugs: (1) prefer atomic-number primitives [#7] over bare letters when aromaticity is not the point; (2) use ; to group across an OR rather than relying on where & binds; (3) always unit-test a new pattern against a small set of molecules with known answers (a "truth table" of molecules) before turning it loose on a library. SMARTS has no type checker — your test molecules are the type checker.

6. Rings and aromaticity in SMARTS

Ring queries deserve their own section because so many real patterns depend on them, and because SMARTS offers several distinct ring primitives that beginners conflate. R with no number means "in any ring"; R0 means "in no ring"; Rn means "in exactly n SSSR rings" (so R2 finds ring-fusion atoms shared by two rings); r with a number, r6, means "in a ring of size 6"; and lowercase element letters (c, n) additionally require aromaticity. The cell maps these onto a fused bicyclic aromatic, indole, where the two rings share two atoms.

# Ring primitives on indole (a benzene fused to a pyrrole) -- a 5- and a 6-ring sharing 2 atoms.
indole = Chem.MolFromSmiles("c1ccc2[nH]ccc2c1")

7. Worked example by hand: matching an amide SMARTS

We now trace the matcher by hand, as promised, on a pattern you will use constantly: the amide group.

Chemistry box — the amide group

An amide is a carbonyl (C=O) bonded to a nitrogen: the linkage −C(=O)−N<. It is the bond that joins amino acids into proteins (the "peptide bond"), and it appears in a large fraction of drugs because it is stable and makes good hydrogen bonds. A sound SMARTS for it is [NX3][CX3]=[OX1]: a three-connected nitrogen, bonded to a three-connected carbon, which is double-bonded to a one-connected oxygen.

Take the molecule N-methylacetamide, SMILES CC(=O)NC. RDKit numbers its atoms in the order they appear in the SMILES string:

mol atom element neighbours H count total connections (X)
0 C 1 3 4 (methyl)
1 C 0, 2, 3 0 3 (carbonyl)
2 O 1 (double) 0 1
3 N 1, 4 1 3
4 C 3 3 4 (N-methyl)

The query [NX3][CX3]=[OX1] has three nodes with constraints and two edges:

query node constraint query edge constraint
q0 N, X3 q0–q1 single (default)
q1 C, X3 q1=q2 double
q2 O, X1

Tracing the backtracking search by hand. We try to place q0 first. q0 needs an N with X3: scanning the molecule, only atom 3 qualifies (it is the only nitrogen, and its total connection count is 2 heavy neighbours + 1 H = 3). So q0 → 3. Next q1 must be a neighbour of atom 3 that is a C with X3: atom 3's neighbours are atoms 1 and 4, both carbons, but atom 4 is a methyl with X4, so only atom 1 (X3) qualifies. So q1 → 1, and the q0–q1 edge maps to the single bond 3–1 (✓ it is single). Finally q2 must be a neighbour of atom 1, double-bonded to it, that is an O with X1: atom 1's remaining neighbours are 0 (carbon, single bond) and 2 (oxygen, double bond); only atom 2 fits. So q2 → 2, and the q1=q2 edge maps to the double bond 1=2 (✓). All three nodes and both edges are satisfied, so the match is the tuple (3, 1, 2) — and it is the only one. The cell confirms every step.

8. A functional-group catalogue: amide, sulfonamide, nitro, Michael acceptor

We now build the hands-on catalogue the syllabus asks for. Each entry is a chemically meaningful group, a SMARTS that recognises it, and a real molecule that contains it. These four groups are a good cross-section: the amide and sulfonamide are binding groups prized in drugs; the nitro and the Michael acceptor are reactive groups that often signal trouble (Section 10). Hand-written SMARTS like these are how most functional-group detectors work, though fully automatic algorithms that partition a molecule into its functional groups without a predefined list also exist.[20]

Chemistry box — the four groups

  • Amide −C(=O)N<: carbonyl bonded to nitrogen; the peptide bond of proteins. SMARTS [NX3][CX3]=[OX1].
  • Sulfonamide −S(=O)(=O)N<: a sulfur bearing two double-bonded oxygens and a nitrogen; the business end of the "sulfa" antibiotics and of many diuretics. SMARTS [SX4](=[OX1])(=[OX1])[NX3].
  • Nitro −NO₂: a nitrogen with two oxygens, usually drawn charge-separated as [N+](=O)[O-]; electron-withdrawing and often metabolised to reactive species. A robust SMARTS must accept both the charged and neutral drawings (a job for recursion, Section 9).

9. Recursive SMARTS: patterns inside patterns

The nitro SMARTS above used a construct we have not yet explained: [$(...)]. This is recursive SMARTS, the feature that lifts the language from "match a fixed skeleton" to "match an atom in a particular environment". A recursive SMARTS $(...) is written as an atomic primitive and means "an atom that is the first atom of a match of the pattern inside the parentheses". It is the SMARTS equivalent of a lookahead in a regular expression: it constrains an atom by what surrounds it, without those surrounding atoms becoming part of the returned match.

Two things make recursion indispensable:

  1. Alternatives. The nitro group has two legitimate drawings — neutral N(=O)=O and charge-separated [N+](=O)[O-]. The pattern [$([NX3](=O)=O),$([NX3+](=O)[O-])] says "a nitrogen that is either of these environments", matching both while still returning only the nitrogen atom.
  2. Context without capture. You often want "a carbon that is attached to a carbonyl" as a single-atom predicate — to then build a larger rule on it — without the carbonyl's atoms appearing in your match. [$([CX4][CX3]=O)] matches exactly that carbon.

The cell demonstrates both uses and contrasts recursive with non-recursive matches so the "first atom only" semantics is unmistakable.

# Recursive SMARTS: match an atom BY ITS ENVIRONMENT, returning only that atom.
mol = Chem.MolFromSmiles("CC(=O)CC(=O)O")            # a keto-acid: two different carbonyls
plain  = Chem.MolFromSmarts("[CX3]=[OX1]")          # non-recursive: returns BOTH atoms (C and O)
recur  = Chem.MolFromSmarts("[$([CX3]=[OX1])]")     # recursive: returns ONLY the carbonyl carbon
print("plain  [CX3]=[OX1]      matches (atom pairs):", mol.GetSubstructMatches(plain))
print("recur  [$([CX3]=[OX1])] matches (single atom):", mol.GetSubstructMatches(recur))

# A context predicate: "a nitrogen attached to an aromatic ring" (an aniline-type N), returning just the N.
aniline_N = Chem.MolFromSmarts("[$([NX3;!$(N=O)][c])]")
for name, smi in [("aniline", "Nc1ccccc1"), ("methylamine", "CN"), ("acetanilide", "CC(=O)Nc1ccccc1")]:
    m = Chem.MolFromSmiles(smi)
    print(f"  {name:12s} aromatic-attached N atoms:", m.GetSubstructMatches(aniline_N))

The contrast is the lesson. The plain pattern [CX3]=[OX1] returns pairs of atom indices (carbon and oxygen) — two carbonyls, two pairs. The recursive [$([CX3]=[OX1])] returns single atoms — just the two carbonyl carbons — because a recursive SMARTS reports only its first atom however large the environment inside the parentheses. The aniline example shows the practical payoff: "a non-nitroso nitrogen bonded to an aromatic carbon" is one atomic predicate you can drop into any larger pattern, and it correctly flags the nitrogen of aniline and acetanilide while rejecting the aliphatic nitrogen of methylamine. Recursion is how professional SMARTS libraries — including the alert sets of the next section — stay both precise and readable.

Chemistry box — why "environment" is the whole game

A chemical group's behaviour depends on its neighbours: an amine on a chain is basic, but an amine next to a carbonyl (an amide) is not; a carbon next to a carbonyl is acidic, an isolated one is not. Recursive SMARTS encodes exactly this "it depends what is next to it" reasoning, which is why it maps so well onto how chemists actually think about reactivity.

10. Screening a library and building a structural-alert catalogue

Everything so far converges on the operation that pays the bills: take a library of molecules and a set of patterns, and report which molecules match which patterns. When the patterns encode undesirable substructures, the set is called a structural-alert (or "filter") catalogue, and running it is the first triage any screening collection receives.

Chemistry box — why some substructures are "alerts"

Three kinds of substructure get flagged. Reactive groups (Michael acceptors, aldehydes, alkyl halides, nitro groups, epoxides) react indiscriminately with proteins and can be toxic or give false readouts — the medicinal-chemistry concern raised by Rishton.[5] Toxicophores are substructures statistically linked to toxicity. PAINS — pan-assay interference compounds — are substructures (catechols, quinones, certain phenols, rhodanines) that appear to "hit" in many unrelated assays because they interfere with the measurement (they absorb light, chelate metals, aggregate, or react) rather than genuinely binding the target. Baell and Holloway distilled these into a now-famous set of substructure filters,[6] and curated reactive/undesirable-group lists such as Brenk's[7] and the Abbott/Bruns–Watson rules[8] serve the same purpose. Every one of these filters is, at bottom, a SMARTS pattern — indeed the PAINS set was re-published in machine-readable SMARTS so that any toolkit can apply it,[21] and the same substructure logic underlies broader "drug-likeness" and library-design filters.[24] Removing troublesome substructures before screening is an old idea; it was already used to decide which compounds to pool and test together in early high-throughput campaigns.[23]

We work with a small, hand-curated library of 36 real molecules — common drugs plus a deliberate salting of reactive and PAINS-flavoured compounds — so the whole screen runs in well under a second. The same code scales unchanged to the million-molecule ChEMBL[9] or ZINC[10] collections (in practice behind a fingerprint pre-screen, Section 2). The library is hard-coded here for a fully reproducible, network-free build; in Colab you would fetch a slice of a real database the same way Units 6–8 do.

Alerts flag; they do not decide

It is tempting to delete every flagged molecule automatically. Do not. The PAINS filters were derived from a single assay technology on one compound collection, and later analyses showed that many "PAINS" never actually misbehave while some clean-looking molecules do — Capuzzi and co-workers called the uncritical use of these alerts "Phantom PAINS".[11] Baell himself revisited their scope a decade on.[12] Treat an alert as a prior, not a proof: it raises the burden of evidence for a molecule, to be settled by orthogonal assays — including, for the common case of colloidal aggregation, dedicated advisory tools and detergent-based counter-screens.[22] The SMARTS is only as good as the data and reasoning behind it — a theme that recurs whenever cheminformatics meets biology.

10.2 How fast is it? The cost of the match

Because a molecular graph is tiny and the element labels prune aggressively (Section 2), an individual substructure test is extremely cheap, which is why screening millions of molecules is feasible. The cell measures the raw throughput of HasSubstructMatch on one molecule so you have a number for the cost model.

# Micro-benchmark: raw substructure-match throughput on a drug-sized molecule.
import time
m = Chem.MolFromSmiles("CC(=O)Oc1ccccc1C(=O)O")      # aspirin, 13 heavy atoms
q = Chem.MolFromSmarts("[CX3]=[OX1]")
N = 20000
t0 = time.perf_counter()
for _ in range(N):
    m.HasSubstructMatch(q)
dt = time.perf_counter() - t0
rate = N / dt
print(f"{N:,} matches in {dt*1000:.0f} ms  ->  {rate:,.0f} matches/second on one core")
print(f"screening 1,000,000 molecules against one pattern: about {1_000_000/rate:.1f} s (single core, no pre-filter)")

The exact-match engine performs on the order of hundreds of thousands of drug-sized substructure tests per second per core, so a single pattern sweeps a million-molecule library in a few seconds even without the fingerprint pre-screen that production systems add — and a whole alert catalogue is just that cost times the number of patterns, trivially parallelised across molecules. The practical lesson for a programmer: substructure search is I/O-bound (reading the library) far more than compute-bound, which is why real deployments store pre-computed fingerprints and molecular graphs rather than re-parsing SMILES on every query,[13] and screen candidates against a fingerprint bit-vector first — tools such as chemfp exist to make exactly this pre-filter fast.[19]

11. Pitfalls when writing SMARTS

Most SMARTS bugs come from a handful of recurring confusions. We have met the biggest two (SMILES-vs-SMARTS parser confusion, Section 1; operator precedence, Section 5); here are the rest, each demonstrated so you recognise it in your own code.

Chemistry box — kekulised vs aromatic, again

RDKit perceives aromaticity when it reads a molecule (Unit 1): benzene's six bonds become type AROMATIC, not alternating single/double. A SMARTS written with explicit double bonds (C=C) therefore does not match an aromatic ring, because an aromatic bond is neither single nor double. To match "a carbon–carbon bond that may be double or aromatic" you write the bond as =,: (double OR aromatic) or match on aromatic atoms with :. Getting this wrong silently misses every aromatic hit — a very common and very quiet bug.

# Aromatic vs aliphatic: a double-bond SMARTS misses benzene; an aromatic/any-bond SMARTS catches it.
benzene = Chem.MolFromSmiles("c1ccccc1")
cyclohexene = Chem.MolFromSmiles("C1CCCCC1".replace("C1CC", "C1=CC"))  # cyclohexene: one real C=C
patterns = {"C=C (double only)": "[#6]=[#6]",
            "c:c (aromatic only)": "[#6]:[#6]",
            "[#6]=,:[#6] (double OR aromatic)": "[#6]=,:[#6]"}
rows = []
for label, sma in patterns.items():
    q = Chem.MolFromSmarts(sma)
    rows.append((label, len(benzene.GetSubstructMatches(q)), len(cyclohexene.GetSubstructMatches(q))))
print(pd.DataFrame(rows, columns=["SMARTS", "matches in benzene", "matches in cyclohexene"]).to_string(index=False))

Figure 8. The aromaticity pitfall made visible. The double-bond pattern [#6]=[#6] finds the single (localised) C=C bond of cyclohexene but nothing in benzene (left panel: no atoms highlighted), because benzene's bonds are aromatic, not double. The =,: bond (double OR aromatic) matches all six benzene bonds (right panel) as well as cyclohexene's alkene. When a SMARTS "mysteriously" misses obvious hits, an unhandled aromatic/aliphatic distinction is the first thing to check.

A short checklist of the remaining traps, each a one-line fix:

  • Explicit vs implicit hydrogens. [OH] and [OH1] mean "oxygen with one attached hydrogen" (a count primitive); the bracket atom [H] means a hydrogen atom as a node, which is almost never what you want. Match hydrogen counts with the H primitive, not with [H] atoms.
  • D vs X vs valence. D counts heavy neighbours, X counts total connections (incl. H), v is the valence (sum of bond orders). Mixing them up is a frequent cause of patterns that are too loose or too strict (Section 3).
  • Charged forms. A group drawn charge-separated (nitro, N-oxide, carboxylate) will not match a neutral SMARTS. Either standardise the molecule first (Unit 4) or write the pattern with recursion to accept both forms (Section 9).
  • Query features are lost on round-trips. Chem.MolToSmiles(queryMol) does not reproduce the SMARTS; to serialise a query use Chem.MolToSmarts. A query molecule is not an ordinary molecule and should not be treated as one.

Bridge — where SMARTS goes next

SMARTS underpins much of the rest of the course. The structural keys of Unit 5 (MACCS) are literally a list of ~166 SMARTS patterns, one per bit. Scaffold and R-group decomposition (Unit 11) use SMARTS to define the core. Reaction transformations (Unit 17) use reaction SMARTS, an extension that maps reactant patterns to product patterns. And the alerts built here become binary features that feed the property and toxicity models of later units — including graph-neural-network tools such as chemprop,[25] which the course describes but, being pure and light, does not run. Learn SMARTS well and a surprising fraction of cheminformatics becomes pattern matching.

12. Summary

You should now be able to explain, without notes:

  • Why a SMILES is a molecule and a SMARTS is a query — the regular-expression analogy — and why MolFromSmiles and MolFromSmarts build different objects.
  • That substructure matching is subgraph isomorphism: NP-complete in general, but fast on molecular graphs because they are tiny, sparse and heavily label-constrained; and that RDKit returns the match as a tuple of molecule-atom indices.
  • The SMARTS atom primitives (element/#n, aromaticity by case, X/D/H counts, charge, R/r ring membership) and bond primitives (-,=,#,:,~,@,!@).
  • The logical operators !, &, ,, ; and their precedence, and why the two ANDs exist (to straddle the OR).
  • Recursive SMARTS [$(...)] and why "an atom in this environment" is the construct that makes real functional-group and alert patterns both precise and readable.
  • How to write SMARTS for the amide, sulfonamide, nitro and Michael-acceptor groups, trace a match by hand, and confirm it with GetSubstructMatches.
  • How to screen a library, build and apply a structural-alert catalogue (by hand and via RDKit's FilterCatalog), highlight the matched atoms, and — crucially — why an alert is a prior for human judgement, not an automatic reject.

13. Self-assessment

1. In one sentence, what is the difference between the SMILES C=O and the SMARTS C=O?The SMILES C=O is a specific molecule (formaldehyde); the SMARTS C=O is a query that matches any aliphatic carbon double-bonded to an oxygen — a carbonyl — in any molecule. They are built by different parsers (MolFromSmiles vs MolFromSmarts) into different kinds of object.
2. Why is substructure search tractable in practice even though subgraph isomorphism is NP-complete?Molecular graphs are tiny (tens of atoms) and sparse (valence caps degree at ~4), and the atom/bond labels prune the backtracking search enormously (a query carbon can map only to carbons). Production systems also apply a cheap fingerprint pre-screen to discard most molecules before the exact match.
3. What does GetSubstructMatches return, and what does position i of a returned tuple mean?A tuple of tuples — one inner tuple per distinct match. Position i of an inner tuple is the index of the molecule atom that the i-th query atom mapped onto; the inner tuple is therefore the subgraph isomorphism, and it is exactly what you pass to highlightAtoms.
4. Distinguish [CD3], [CX3] and [CH3].[CD3]: a carbon with 3 explicit (heavy-atom) connections. [CX3]: a carbon with 3 total connections including hydrogens. [CH3]: a carbon with exactly 3 attached hydrogens (a methyl). A carbonyl carbon is [CX3] and [CD3] but not [CH3]; a methyl is [CX4], [CD1] and [CH3].
5. How does [C,N;H1] differ from [C,NH1], and why?[C,N;H1] = (carbon OR nitrogen) AND exactly-one-H, because ; is a low-precedence AND that binds looser than the OR. [C,NH1] = carbon OR (nitrogen AND one-H), because the implicit & binds tighter than the comma. Precedence: ! > & > , > ;.
6. Write a SMARTS for an aromatic nitrogen that carries a hydrogen (like the N–H of pyrrole), and say why case matters.[nH] (or [n;H1]). Lowercase n requires the nitrogen to be aromatic; uppercase N would match only an aliphatic nitrogen and miss every aromatic one. Case encodes aromaticity in SMARTS.
7. Trace by hand: does [NX3][CX3]=[OX1] match acetamide CC(=O)N? Give the match tuple.Yes. The nitrogen (3 total connections: 1 heavy + 2 H) is [NX3]; the carbonyl carbon (3 total connections) is [CX3]; the oxygen (1 connection, double bond) is [OX1]; the N–C bond is single and the C=O bond is double. With RDKit's atom order for CC(=O)N (0 methyl C, 1 carbonyl C, 2 O, 3 N) the match is (3, 1, 2).
8. What is a recursive SMARTS, and how many atoms does [$([CX3]=[OX1])] return per carbonyl?A recursive SMARTS $(...) is an atomic predicate that is true when the atom is the first atom of a match of the inner pattern — a "lookahead". [$([CX3]=[OX1])] returns exactly one atom per carbonyl (the carbon), because a recursive SMARTS reports only its first atom, not the whole environment.
9. Why must the nitro SMARTS be written [$([NX3](=O)=O),$([NX3+](=O)[O-])] rather than just N(=O)=O?Because nitro groups are usually drawn charge-separated as [N+](=O)[O-], which a neutral N(=O)=O would miss. The two recursive alternatives (joined by OR) accept both the neutral and the charged drawings while still returning only the nitrogen atom.
10. A reviewer says "just delete every molecule that trips a PAINS filter." What is the problem?PAINS alerts were derived from one assay technology on one library; later work ("Phantom PAINS") showed many flagged molecules never interfere while some unflagged ones do. An alert is a prior that raises the burden of proof — to be resolved by orthogonal assays and aggregation checks — not an automatic reject. Deleting indiscriminately discards good chemistry and keeps hidden offenders.
11. Why does [#6]=[#6] fail to match any bond in benzene, and what should you write instead?Benzene's bonds are perceived as aromatic, not double, so an explicit double-bond query matches none of them. Use [#6]:[#6] (aromatic) or [#6]=,:[#6] (double OR aromatic) to catch aromatic C–C bonds.
12. Roughly how long does a single-pattern substructure sweep of a million molecules take on one core, from the benchmark, and what is the real bottleneck in production?A few seconds — the matcher does on the order of 10⁵–10⁶ drug-sized tests per second per core. In production the bottleneck is I/O (reading and parsing the library), which is why systems store pre-computed graphs and fingerprints and apply a fingerprint pre-screen before the exact match.

Glossary

SMARTS
A query language for molecular substructures; a pattern (atoms + bonds + logic) that matches a set of molecules. The molecular analogue of a regular expression.
SMILES
A text serialisation of one specific molecule (Unit 3); parsed by MolFromSmiles, whereas a SMARTS is parsed by MolFromSmarts.
Substructure
Any connected set of atoms and the bonds between them within a molecule.
Subgraph isomorphism
The problem of deciding whether one labelled graph (the query) is isomorphic to a subgraph of another (the molecule); NP-complete in general, the formal basis of substructure search.
Query molecule
The object built by MolFromSmarts: atoms and bonds carry constraints (predicates) rather than fixed values.
Atom / bond primitive
A single SMARTS predicate on an atom (element, aromaticity, charge, X/D/H count, ring membership) or a bond (-,=,#,:,~,@).
Logical operators
SMARTS combinators ! (not), & (high-precedence and), , (or), ; (low-precedence and), in that precedence order.
Recursive SMARTS
The construct [$(...)]: an atomic predicate true when the atom is the first atom of a match of the inner pattern — an environment constraint / lookahead.
Functional group
A small substructure with characteristic chemistry (amide, sulfonamide, nitro, Michael acceptor, …).
Michael acceptor
An α,β-unsaturated carbonyl (C=C−C=O) that reacts with nucleophiles; useful for covalent drugs, a liability in random screening hits.
Structural alert / filter
A substructure whose presence flags a molecule as potentially reactive, toxic or assay-interfering; implemented as a SMARTS.
PAINS
Pan-assay interference compounds: substructure classes that appear active across many unrelated assays by interfering with the measurement rather than binding the target.
Toxicophore
A substructure statistically associated with toxicity.
Kekulisation
Rewriting an aromatic ring with localised alternating single/double bonds; relevant because an aromatic bond is matched by neither a single- nor a double-bond SMARTS.
FilterCatalog
RDKit's API holding curated SMARTS alert sets (PAINS, Brenk, NIH, …) ready to apply to molecules.
