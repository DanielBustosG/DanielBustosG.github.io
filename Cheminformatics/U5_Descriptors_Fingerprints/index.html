Every method in the rest of this course — similarity search, clustering, drug-likeness filters, QSAR, machine learning, generative design — takes a vector as input, not a molecule. This unit is the hinge on which the course turns: it is where a molecular graph becomes a fixed list of numbers a computer can measure distances between and feed to a model. We build the two great families of molecular vector — descriptors (each number means something physical) and fingerprints (a bit vector recording which substructures are present) — and we open the most important one, the circular (ECFP/Morgan) fingerprint, all the way down to the bits, tracing its hashing by hand on a three-atom molecule and confirming every bit in code. By the end you will be able to turn any structure into a vector, measure how similar two molecules are, and explain exactly what that number does and does not mean.

1. From a molecule to a vector

A computer cannot compute a distance between two molecular graphs directly — graphs have no fixed length and no natural coordinate system. The universal move of cheminformatics is therefore to featurise: map each molecule to a fixed-length vector of numbers, so that the whole toolbox of statistics and machine learning becomes available. Two vectors can be subtracted, correlated, clustered, fed to a random forest. Everything downstream in this course is an operation on these vectors.

There are two historically distinct ways to build the vector, and they answer two different questions.

  • A descriptor vector answers "what are this molecule's properties?" Each entry is an interpretable number — molecular weight, lipophilicity, polar surface area, a count of rings — computed from the structure. The vector is short (a handful to a few hundred numbers) and every coordinate has a meaning.
  • A fingerprint answers "which pieces is this molecule made of?" It is a long binary vector in which each bit records the presence or absence of a particular substructural pattern. The vector is long (hundreds to thousands of bits), sparse, and individual coordinates are usually not interpretable, but the whole vector is an extremely faithful fingerprint of the structure — hence the name.

The cell below makes both vectors for a single molecule, aspirin, so you can see their very different shapes before we study each in depth. Chemistry box — a descriptor, a fingerprint, a substructure

A descriptor is any single number computed from a molecule's structure that summarises a property: its weight, its greasiness, how many rotatable bonds it has. A fingerprint is a (usually binary) vector in which each position stands for a structural feature and the bit says whether the molecule has that feature. A substructure is simply a connected piece of the molecular graph — a group of atoms and the bonds between them, such as a hydroxyl (-OH) group or a benzene ring. Fingerprints are built from substructures. For a computer scientist: a descriptor vector is hand-engineered features; a fingerprint is a feature hash of the graph's subgraphs.

2. Molecular descriptors

2.1 What a descriptor measures

The physicochemical descriptors you will use most are exactly the properties Unit 1 introduced, now treated as the coordinates of a vector. They fall into loose families.[9]

  • Constitutional descriptors just count things: molecular weight, number of atoms of each element, number of rings, number of rotatable bonds. A rotatable bond is a single bond, not in a ring, between two non-terminal heavy atoms; the count estimates molecular flexibility, because each such bond lets one part of the molecule swivel relative to another.
  • Topological descriptors are computed from the molecular graph's connectivity without any 3-D information. The oldest is the Wiener index (1947), the sum of the number of bonds on the shortest path between every pair of atoms — the first time a physical property (boiling point) was predicted from a graph invariant.[10] The Randić branching index and Kier–Hall connectivity and electrotopological-state indices refined this idea into a whole family of graph descriptors.[11][12]
  • Physicochemical descriptors estimate a measurable physical quantity from structure: logP (lipophilicity) by the Crippen atom-contribution method,[6] and TPSA (topological polar surface area), the summed surface of polar N/O atoms, from Ertl's fragment method.[7] Hydrogen-bond-donor (HBD) and acceptor (HBA) counts, and the number of aromatic rings, round out the set.
  • A composite descriptor combines several into a single score. QED (quantitative estimate of drug-likeness) blends eight properties into one number in [0, 1] that rises with how "drug-like" a molecule looks.[5]

2.2 Descriptors live on different scales

Molecular weight runs into the hundreds; logP ranges from about -3 to +7; a hydrogen-bond-donor count is a small integer. If you feed such columns directly to any method that measures distance — k-nearest-neighbours, support-vector machines, k-means, PCA — molecular weight will dominate simply because its numbers are bigger, not because it matters more. The fix is standardisation: rescale each column to have mean 0 and standard deviation 1 (a z-score), so every descriptor contributes comparably. This is ordinary machine-learning hygiene, but it is easy to forget when the columns look like chemistry rather than features.

Pitfall — scaling leaks if you do it wrong

Fit the scaler on the training set only, then apply it to the test set; fitting it on all the data lets information about the test set leak into training and inflates your scores. We return to this in Unit 14. Here we scaled the whole eight-row table only to display the effect.

3. Fingerprints: a molecule as a bit vector

A fingerprint turns a molecule into a long binary vector by asking, for each of many substructural features, "is this feature present?" The result is a bit string that is extraordinarily characteristic of the structure — two molecules with nearly identical fingerprints are almost always nearly identical molecules. For a computer scientist the cleanest analogy is a feature hash: a fingerprint maps a variable set of items (the molecule's subgraphs) into a fixed-length vector, exactly as hashing a document's words into a bag-of-words vector. There are two design philosophies, which we take in turn.

3.1 Structural keys: MACCS

The oldest and simplest design is a structural key: fix a dictionary of substructure questions in advance, give each its own bit, and set the bit if the molecule answers "yes". The best-known public example is the MACCS keys — a list of 166 predefined substructure patterns (RDKit returns 167 bits, bit 0 being unused) such as "has a nitrogen", "has a 6-membered aromatic ring", "has two oxygens three bonds apart".[3] Because each bit has a fixed, human-readable meaning, MACCS is interpretable; because the dictionary is small and generic, it is coarse. The weakness of a fixed dictionary is obvious: it can only ask questions someone thought to include. A substructure that distinguishes two molecules but is not in the 166-key list is invisible. That is the motivation for the second design philosophy, which invents the features automatically from each molecule.

3.2 Hashed topological (path) fingerprints

Instead of a fixed dictionary, a hashed fingerprint enumerates features directly from the molecule and hashes each one to a bit position in a vector of chosen length. The classic example is the RDKit/Daylight topological fingerprint: it finds every linear path of bonded atoms up to some length, turns each path into a short integer, and hashes that integer to one (or a few) bits. No dictionary is needed — the features are whatever paths the molecule contains — but the price is that individual bits are no longer interpretable, and two different paths can hash to the same bit (a collision, Section 6). Other hashed designs enumerate different features from the same graph: atom-pair fingerprints hash every pair of atoms together with the topological distance between them,[13] and topological-torsion fingerprints hash every linear sequence of four bonded atoms.[14] More recent schemes such as MAP4 combine atom-pair distances with circular environments to cover both small molecules and larger biomolecules.[25]

4. Circular fingerprints (ECFP / Morgan): the central representation

A circular fingerprint describes a molecule by the set of atom environments it contains. For each atom it records the atom itself, then the atom together with its immediate neighbours, then together with neighbours-of-neighbours, and so on out to a chosen radius. Each such environment is hashed to an integer identifier, and the set of all identifiers (folded into a bit vector) is the fingerprint. The idea descends from a 1965 algorithm of H. L. Morgan for assigning canonical atom labels by iterative neighbourhood refinement,[2] and was formalised as the Extended-Connectivity Fingerprint (ECFP) by Rogers and Hahn in 2010.[1] RDKit's implementation is called the Morgan fingerprint; it is the same algorithm.

Chemistry box — an atom environment

An atom environment of radius r around a given atom is the sub-molecule consisting of that atom plus every atom within r bonds of it, with all the bonds among them. Radius 0 is just the atom itself (with its element, charge and hydrogen count); radius 1 adds its direct bonded neighbours; radius 2 adds their neighbours. Chemically, an environment captures a local functional context — "an oxygen bonded to a carbonyl carbon" is a radius-1 environment that means "part of an acid or ester". A circular fingerprint is the bag of all such local contexts in the molecule.

ECFP4, ECFP6 — what the number means

The number in ECFP4 is the diameter, which is twice the radius. ECFP4 means radius 2; ECFP6 means radius 3. RDKit's GetMorganGenerator(radius=2, ...) is therefore ECFP4 — the most common default. We use radius 2 throughout.

# The set of atom environments grows as the radius increases; ECFP collects them all.
asp = mols["aspirin"]
for r in [0, 1, 2, 3]:
    sparse = AllChem.GetMorganFingerprint(asp, r)      # unfolded: one integer per distinct environment
    n_env = len(sparse.GetNonzeroElements())
    print(f"radius {r}: {n_env:3d} distinct atom environments in aspirin "
          f"({'atoms only' if r==0 else 'up to '+str(r)+'-bond neighbourhoods'})")
print("\naspirin has", asp.GetNumAtoms(), "heavy atoms; radius-0 environments can be fewer than atoms",
      "when two atoms are identical (symmetry).")

The count rises with radius because larger neighbourhoods are more specific, so fewer atoms share one. At radius 0 the count can be smaller than the number of atoms, because chemically identical atoms (the symmetry-equivalent CH groups of the benzene ring) collapse to the same environment — a fact we exploit in the hand trace next. ECFP collects the environments at every radius from 0 up to the chosen maximum, so a radius-2 fingerprint contains all the radius-0, radius-1 and radius-2 identifiers.

5. Worked example by hand: tracing the Morgan algorithm on ethanol

This is the worked example of the unit. We will compute the Morgan fingerprint of ethanol (CCO, three heavy atoms) entirely by hand, then confirm every bit with RDKit. Three atoms is small enough to do on paper and rich enough to show the whole algorithm.

The algorithm has three steps, repeated once per radius.

  1. Initial identifiers (radius 0). Give each atom an integer that encodes its own chemistry. RDKit builds a tuple of six atomic properties — atomic number, heavy-atom degree, number of attached hydrogens, formal charge, isotope mass difference, and whether the atom is in a ring — and hashes that tuple to a 32-bit integer.[1] Two atoms get the same radius-0 identifier exactly when those six properties match.
  2. Update (radius 1, 2, ...). For each atom, form a new identifier by hashing together the current radius number, the atom's own current identifier, and the sorted list of (bond order, neighbour's current identifier) pairs. This folds each atom's neighbourhood one bond further out, exactly as Morgan's 1965 refinement did.
  3. Collect and fold. Gather every identifier produced at every radius; each is reduced to a bit position by taking it modulo the fingerprint length (here 2048). Set those bits.

6. Counts versus bits, folding and collisions

Two practical facts complete the picture of how a fingerprint is stored.

First, counts versus bits. The fingerprints above are binary: a bit is 1 if an environment is present, regardless of how many times. A count fingerprint instead stores how many times each environment occurs. Counts carry more information (a molecule with three amide groups differs from one with a single amide), and sometimes help models, but the binary form is smaller and is the default for similarity.

Second, folding and collisions. An environment's raw identifier is a 32-bit integer — there are about four billion possible values, far more than we want to store. We fold the identifier into a vector of manageable length (1024, 2048, 4096 bits) by taking it modulo that length, exactly as a hash table maps keys into buckets. The inevitable consequence, as in any hash table, is a collision: two chemically different environments whose identifiers happen to be congruent modulo the fingerprint length land on the same bit. A collision means one bit now ambiguously signals "environment A or environment B", a small loss of information. The next cells show both facts.

7. Measuring molecular similarity

A fingerprint is useful chiefly because it lets us compare molecules. The comparison is a set operation: treat each fingerprint as the set of features (bits) that are on, and ask how much two sets overlap.

Chemistry box — what "molecular similarity" means

There is no single physical definition of how similar two molecules are; it depends on what you care about (shape, electronics, which bits of structure). In practice "similarity" means fingerprint overlap: two molecules are similar if they share many substructural features. This is a pragmatic, operational definition, and most of the art is in remembering that it is only a proxy for the chemistry or biology you actually care about.[15][17][26]

The standard coefficient is the Tanimoto (Jaccard) similarity. For two bit sets A and B,

$$T(A,B) = \frac{|A \cap B|}{|A \cup B|} = \frac{c}{a + b - c}$$ where $a$ and $b$ are the numbers of bits set in A and B and $c$ is the number set in both. It runs from 0 (no shared bits) to 1 (identical bit sets).

Two close relatives weight the shared bits differently: Dice uses $2c/(a+b)$ and cosine uses $c/\sqrt{ab}$. The Tanimoto coefficient is named after a 1960 classification method of Rogers and Tanimoto;[16] a 2015 analysis explains why it, rather than the alternatives, became the cheminformatics standard.[4]

7.1 Tanimoto by hand

Take two tiny fingerprints of eight bits each — the kind you might get from a toy featuriser — and compute their Tanimoto by hand before confirming with RDKit.

Let A = {bits 0, 2, 3, 5, 6} and B = {bits 2, 3, 4, 6, 7}. Then a = 5, b = 5; the shared bits are {2, 3, 6}, so c = 3; the union is {0, 2, 3, 4, 5, 6, 7}, size 7. Therefore T = 3 / (5 + 5 − 3) = 3 / 7 ≈ 0.4286. Dice = 2·3/(5+5) = 0.6; cosine = 3/√(5·5) = 0.6. The cell confirms all three.

8. The similar-property principle

Why do we care about fingerprint similarity at all? Because of an empirical regularity that underlies nearly all of ligand-based drug discovery.

Chemistry box — the similar-property principle

The similar-property principle states that structurally similar molecules tend to have similar properties and biological activities.[30] It is the reason a chemist, having found one active compound, looks next at its close analogues. It is a statistical tendency, not a law — and the exceptions, where a tiny change flips activity, are themselves highly informative (Section 8.1). Here "activity" means how strongly a molecule acts on a biological target; it is often reported as pIC50 or pChEMBL, the negative base-10 logarithm of the concentration needed for an effect, so that bigger means more potent.

8.1 Where the principle fails: activity cliffs

The similar-property principle is a tendency, and its most interesting failures are activity cliffs: pairs of molecules that are highly similar yet have very different activity.[20] A single methyl group added in the right place can turn a potent inhibitor into an inactive one, because that one change clashes with the binding site. Cliffs are precisely the cases where a similarity-only search misleads, and precisely the cases a medicinal chemist most wants to understand — they pinpoint what the target "cares about". A famous early warning, Martin and colleagues' 2002 study, found that two molecules with ECFP Tanimoto above 0.85 have only about a 30 % chance of sharing activity — similarity raises the odds but is far from a guarantee.[18] We analyse cliffs and the structure–activity landscape properly in Unit 11; for now, hold the caveat: similarity is a powerful prior, never a proof.

9. Choosing a representation

You now have three representations — descriptors, structural keys (MACCS) and circular fingerprints (ECFP) — and a measure of similarity. Which to use? A compact guide:

  • Interpretable model, small data, physical story wanted: physicochemical descriptors (scaled). You can read the coefficients (Unit 12).
  • Similarity search, clustering, diversity selection: ECFP4 with Tanimoto. It is the field default for a reason.[21][23]
  • Fast, interpretable substructure screening or a quick baseline: MACCS. Coarse but transparent.
  • Machine-learning property prediction: usually ECFP4 (2048 bits), sometimes concatenated with descriptors; tree models and SVMs handle the sparse vector well (Unit 13).

The two families are not interchangeable: they can disagree about which molecule is "nearest" to a query, because they measure different things (shared properties versus shared substructures). The final cell shows such a disagreement.

The two rankings need not match: descriptor distance can call a molecule "near" because it happens to have a similar weight and logP, while the fingerprint correctly sees that it shares no scaffold. Neither is wrong — they answer different questions. The practical advice is to pick the representation that matches your task (property story → descriptors; structural neighbour → fingerprint) and to state it explicitly, because every downstream result inherits the choice made here.[29]

11. Self-assessment

1. A colleague feeds raw descriptors (MW, logP, HBD) straight into k-nearest-neighbours and gets strange results. What is the likely bug?No standardisation. MW is in the hundreds while HBD is a small integer, so Euclidean distance is dominated by MW and the other descriptors barely count. Z-score each column (fit the scaler on training data only) before any distance-based method.
2. What does the "4" in ECFP4 refer to, and what RDKit radius does it correspond to?The diameter, which is twice the radius. ECFP4 = radius 2; ECFP6 = radius 3. In RDKit, GetMorganGenerator(radius=2) is ECFP4.
3. In the ethanol trace, why do the three atoms get three distinct radius-0 identifiers?Because the radius-0 identifier hashes the atom's own properties (atomic number, degree, H count, charge, ring membership) and the three atoms differ: a CH3 carbon (degree 1, 3 H), a CH2 carbon (degree 2, 2 H) and an OH oxygen (degree 1, 1 H, element O). Different property tuples hash to different identifiers.
4. How is the radius-1 identifier of an atom computed from radius-0 identifiers?By hashing together the radius number, the atom's own radius-0 identifier, and the sorted list of (bond order, neighbour's radius-0 identifier) pairs. This folds the neighbourhood one bond further out; repeating it gives radius 2, 3, and so on.
5. A 32-bit identifier is folded to a 2048-bit fingerprint. By what operation, and what is the unavoidable consequence?By taking the identifier modulo 2048 (as a hash table maps keys to buckets). The consequence is collisions: two different environments whose identifiers are congruent mod 2048 share a bit, so that bit becomes ambiguous. Larger fingerprints collide less.
6. Two molecules have fingerprints with a = 20 and b = 24 bits set, sharing c = 12. Give their Tanimoto and Dice.Tanimoto = 12 / (20 + 24 - 12) = 12/32 = 0.375. Dice = 2*12 / (20 + 24) = 24/44 ≈ 0.545. Dice is always at least as large as Tanimoto for the same pair.
7. You compute MACCS Tanimoto 0.7 and ECFP4 Tanimoto 0.4 for the same pair. Is one wrong?No. The two fingerprints measure different features, so their similarity scales differ; MACCS's generic keys are easy to share and read high. Values are only comparable within one fingerprint type. Report which fingerprint and radius you used.
8. State the similar-property principle and one way it fails.Structurally similar molecules tend to have similar properties/activities. It fails at activity cliffs: pairs of very similar molecules with very different activity, where a small structural change clashes with (or newly fits) the binding site.
9. Why can a binary and a count fingerprint of the same molecule give different model inputs?The binary form records only presence/absence of each environment; the count form records how many times it occurs. A molecule with three equivalent amide groups is identical to a one-amide molecule on those bits in binary, but differs in counts. Counts carry multiplicity information.
10. Why does a larger molecule generally set more bits in a hashed fingerprint?It contains more distinct substructural features (paths or atom environments), each hashing to a bit; more features means more bits set, until collisions start to merge them in a short vector.
11. You must choose a representation to build an interpretable logP model with 60 compounds. Descriptors or ECFP? Why?Descriptors. With few samples and a need to read the model, a handful of scaled physicochemical descriptors gives interpretable coefficients; a 2048-bit ECFP would be high-dimensional, sparse and uninterpretable, and prone to overfit 60 points.
12. Descriptor-distance and fingerprint-distance disagree on the nearest neighbour of a query. Who is right?Neither; they answer different questions. Descriptor Euclidean distance asks "similar bulk properties?"; Tanimoto on ECFP asks "shared substructures?". Choose the one matching your task and state it; the whole downstream pipeline inherits the choice.

Glossary

Atom environment
The sub-molecule formed by an atom plus all atoms within a given radius (in bonds) and the bonds among them; the unit a circular fingerprint hashes.
Circular fingerprint (ECFP / Morgan)
A fingerprint built from the set of atom environments up to a chosen radius; RDKit's Morgan fingerprint. ECFP4 = radius 2.
Collision
Two different features mapping to the same bit because their identifiers are congruent modulo the fingerprint length.
Cosine / Dice / Tanimoto
Similarity coefficients on bit sets; Tanimoto (Jaccard) = shared / union is the cheminformatics standard.
Count fingerprint
A fingerprint that stores how many times each feature occurs, rather than just presence/absence.
Descriptor
A single number computed from structure that summarises a property (MW, logP, TPSA, ring count, QED...).
Fingerprint
A (usually binary) vector in which each position records the presence of a substructural feature.
Folding
Reducing a large feature identifier to a bit position by taking it modulo the fingerprint length.
logP
Octanol/water partition coefficient (log scale); a measure of lipophilicity, estimated here by the Crippen method.
MACCS keys
A fixed dictionary of 166 (RDKit: 167-bit) predefined substructure patterns, one meaning per bit.
pIC50 / pChEMBL
The negative base-10 logarithm of a potency concentration; larger means more potent. pChEMBL is ChEMBL's harmonised version.
Radius
How many bonds out from each atom a circular fingerprint reaches; diameter = 2 x radius (ECFP4 = radius 2).
Rotatable bond
A non-ring single bond between two non-terminal heavy atoms; counts estimate molecular flexibility.
Similar-property principle
The empirical tendency of structurally similar molecules to have similar properties and activities.
Standardisation (z-score)
Rescaling a feature column to mean 0 and standard deviation 1 so all features contribute comparably.
TPSA
Topological polar surface area; the summed surface of polar (N/O) atoms, tracking water affinity.
