Every method in the rest of this course consumes data: a list of molecules, usually with a measured number attached. That data does not come from nowhere. It lives in a handful of large, public, carefully curated databases, and knowing how they are organised — what an entry means, which identifier keys join one database to another, and how a measured "activity" is defined — is as much a part of cheminformatics as any algorithm. This unit is the bridge between the representation layer you have just learned (Units 3-5) and the modelling you are about to do (Units 7 onward): it teaches you where real molecular data comes from, what its pieces mean, and how to pull a clean, target-specific slice of it with a few lines of Python.

1. The public chemical databases, and why they exist

A molecule on its own is just a graph (Unit 1). What makes it useful for discovery is everything attached to it: who made it, what it does to which protein, how tightly it binds, whether it is a known drug, and where to buy it. That attached knowledge is scattered across a small number of public databases, each built by a different community for a different purpose. A cheminformatician spends a surprising fraction of their time knowing which database answers which question and how to get data out of it cleanly.

Before we can read any of them we need four pieces of biological vocabulary, because the databases are organised around them.

Chemistry box — target, assay, activity, potency

A target is the biological molecule a drug is meant to act on — almost always a protein, such as an enzyme or a receptor. ("Target" because it is what the drug aims at.) An assay is a laboratory experiment that measures what a compound does to a target or to cells — think of it as one reproducible measurement protocol. An activity (or bioactivity) is a single number that comes out of an assay: how much compound was needed to produce an effect. Potency is the informal word for "how little compound you need" — a more potent compound works at a lower concentration. Hold these four words; the entire bioactivity data model is just targets that have assays that produce activities for compounds.

The major resources divide cleanly by what they store. The cell below lays out the ones this unit uses, with the kind of content, the approximate scale, the primary identifier each assigns, and the licence — the last column matters more than beginners expect, because it decides what you are allowed to redistribute.

It is worth pausing on why resources like these exist at all, because the answer shapes how you must treat them. None of this data was born digital and tidy. ChEMBL's bioactivities were read out of tens of thousands of medicinal-chemistry papers and patents by human curators, normalised to common units and structure representations, and re-released as periodic, versioned snapshots as the collection grew and the extraction pipeline improved.[3] That provenance has two consequences you will feel in every later unit. First, the data is heterogeneous by construction: it aggregates measurements made by different laboratories, with different protocols, over three decades, so apparent disagreements between records are the norm rather than the exception. Second, the data is a moving target: the ChEMBL you query today is a specific release, and the same query against a later release will return more (and sometimes revised) rows. A computer scientist used to a static training set should internalise early that a chemical database is a living, curated, versioned artefact — closer to a continuously edited encyclopaedia than to a fixed file — and that reproducibility therefore depends on pinning the version, a point we return to at the end of the unit. The pay-off of all this curation effort is enormous: because these resources are open, a student with a laptop and a Colab notebook can now interrogate essentially the entire public record of what small molecules do to biological targets, something that two decades ago was the private advantage of a few large pharmaceutical companies.

2. Identifier systems: the primary keys of chemistry

To join two databases you need a shared key. In chemistry there is no single universal key; there are several, each with a different scope and a different failure mode. A computer scientist should think of them exactly as database keys, some surrogate (assigned by an authority) and some natural (derived from the structure itself).

Chemistry box — the four kinds of chemical identifier

A registry number is a surrogate key assigned by an authority and meaningless on its own: the CAS number (from the Chemical Abstracts Service) and a database accession such as a ChEMBL ID (CHEMBL25), a PubChem CID (a compound identifier) or a DrugBank ID are all of this kind — stable, but you must look them up. A structural identifier is a natural key computed from the molecular graph: canonical SMILES (Unit 3) and especially the InChIKey, a fixed-length hash of the IUPAC InChI string, let two systems decide whether they hold "the same molecule" without a central registry. For a protein target the key is a UniProt accession (e.g. P00533), the standard identifier for a protein sequence.

Why so many keys? Because each was designed to solve a different problem, and none solves all of them. The CAS number is authoritative and covers almost every known substance, but it is proprietary and not freely redistributable, so open databases cannot lean on it. A database accession (ChEMBL ID, CID, DrugBank ID) is free and stable but local: it is meaningful only inside the database that minted it, and the same molecule carries a different accession in each. A canonical SMILES is free and structure-derived, but it is a variable-length string whose exact form depends on which toolkit and which algorithm canonicalised it, so two systems can hold the same molecule as two different SMILES. The InChIKey was engineered precisely to be the missing universal, free, fixed-length, structure-derived key — a short hash that any toolkit computes identically from the structure, so it can serve as a join column across sources that share no accession scheme. No single identifier is "the" right one; a working cheminformatician keeps several and knows which to use for which join.

The InChIKey deserves special attention because it is the closest thing cheminformatics has to a universal content-addressed key — the chemical analogue of a git commit hash. The cell takes one well-known drug, gefitinib (an anticancer kinase inhibitor), and shows the same molecule through five identifier systems at once, computing the structural keys with RDKit from its SMILES.

The CAS number, ChEMBL ID, CID and DrugBank ID are opaque: you cannot derive one from another, you must look them up in the owning database. The SMILES and the InChIKey, by contrast, are computed from the structure — we generated them from the graph with two RDKit calls. That is what makes the InChIKey the key of choice for de-duplication across sources: if two records anywhere in the world produce the same InChIKey, they are (to the resolution of the InChI standard) the same compound.

The InChIKey has a readable anatomy. It is 27 characters in three hyphen-separated blocks: a 14-character block that hashes the molecular skeleton (atoms and bonds), an 8-character block that hashes the remaining layers (stereochemistry, isotopes, protonation), a single flag character for the InChI version and protonation, and a final check character. Two molecules that differ only in stereochemistry share the first block but differ in the second — a property we can see directly.

# Dissect the InChIKey, and show that stereoisomers share the first (skeleton) block but differ in the second.

    skeleton, rest = key.split("-")[0], key.split("-")[1]
    return skeleton, rest[:8], rest[8]            # 14-char skeleton, 8-char layer hash, version/protonation flag

3. The bioactivity data model: target → assay → activity

ChEMBL, BindingDB and the bioassay part of PubChem all share one data model, and understanding it is the difference between fetching numbers you can trust and fetching noise. The model is a chain:

  • a target (identified by a ChEMBL target ID and, for a protein, a UniProt accession) is the protein or system under study;
  • a target has many assays (each with its own ChEMBL assay ID and a free-text description of the exact protocol);
  • each assay produces many activities, and every activity links one compound (a ChEMBL molecule ID) to one measured value with a type (IC50, Ki, …), a relation (=, >, <), a number and a unit.

So a single activity record is a five-way join: compound × assay × target × (type, relation, value, unit) × the document it was published in. The cell fetches one real activity record for the epidermal growth factor receptor (EGFR, a cancer drug target) and prints the pieces of that join, so the abstract model becomes a concrete row. 4. What the activity numbers mean: IC50, Ki, EC50 and Kd

The type of an activity is not a detail; it changes what the number means and whether two numbers can be compared. All four common types are concentrations (so lower means more potent), but they measure different things.

Chemistry box — the four potency measures

IC50 (half-maximal inhibitory concentration): the concentration of compound that cuts a measured activity in half. It is the workhorse of the literature but it is assay-dependent — it shifts with the amount of substrate used. EC50 is the same idea for a stimulatory (effective) effect rather than inhibition. Ki (inhibition constant) and Kd (dissociation constant) are true binding constants: they describe how tightly the compound sticks to the target and, unlike IC50, do not depend on the assay's substrate concentration. The Cheng–Prusoff equation[20] converts an IC50 to a Ki if you know the assay conditions — which is exactly why mixing raw IC50 values from different assays is risky. For all four, a smaller number means a more potent compound.

It helps to picture where these numbers come from. An assay does not report a single concentration; it measures the effect at several concentrations and fits a smooth dose-response curve — effect plotted against the logarithm of concentration, typically an S-shaped (sigmoidal) curve. The IC50 or EC50 is simply the concentration at the curve's midpoint, the point of half-maximal effect. This is why the value is a concentration and why, for a well-behaved assay, it summarises an entire experiment in one number. It is also why the measurement is fragile: if the curve is shallow, incomplete, or the compound is poorly soluble at the top concentrations, the fitted midpoint can be off by a large factor, and that uncertainty is baked into the single number the database stores. Binding constants (Ki, Kd) come from a different experimental setup that measures the compound sticking to and coming off the target directly, which is why they are cleaner but scarcer: they are harder and more expensive to measure, so laboratories report far fewer of them, as the counts below will show.

How much data of each type exists depends heavily on the target. The cell asks ChEMBL how many measurements of each type it holds for EGFR, using the cheap trick of reading the total_count field from a one-row query. It falls back to the counts recorded at the time this notebook was written.

# How many measurements of each type does ChEMBL hold for EGFR? Read total_count from a 1-row query per type.

5. Making potencies comparable: pIC50 and pChEMBL

Raw potency values span an enormous range — from sub-nanomolar (very potent) to millimolar (very weak), six or more orders of magnitude — and they are right-skewed, which is bad for both plotting and modelling. The fix is the one you would reach for with any multiplicative, wide-range quantity: take a logarithm. The standard transform is

$$\text{pIC50} = -\log_{10}\big(\text{IC50 in mol/L}\big) = 9 - \log_{10}\big(\text{IC50 in nM}\big)$$ The second form is the handy one because ChEMBL reports most potencies in nanomolar (nM). A pIC50 of 9 is 1 nM; 7 is 100 nM; 5 is 10 µM. Higher pIC50 = more potent. ChEMBL publishes a standardised version of this, pChEMBL, defined as −log10 of the molar value for a comparable set of types (IC50, EC50, Ki, Kd, potency), so that one column is directly comparable where the underlying measurement allows it.

This is a perfect small algorithm to trace by hand before trusting any code. Take three IC50 values: 1 nM, 41 nM and 10000 nM. By hand, $\text{pIC50}(1) = 9 - \log_{10}1 = 9 - 0 = 9$; $\text{pIC50}(41) = 9 - \log_{10}41 = 9 - 1.613 = 7.39$; $\text{pIC50}(10000) = 9 - \log_{10}10^{4} = 9 - 4 = 5$. Notice the middle one reproduces the pChEMBL of 7.39 we saw in the raw record for the 41 nM compound — a good sign the definition is right. The cell confirms the arithmetic and checks it against ChEMBL's own pChEMBL where available.

# Trace pIC50 = 9 - log10(nM) by hand, then confirm with code; compare to ChEMBL's pChEMBL for the 41 nM record.
examples_nM = np.array([1.0, 41.0, 100.0, 10000.0])
by_hand     = np.array([9.0, 7.39, 7.0, 5.0])                 # computed on paper in the prose above
by_code     = 9.0 - np.log10(examples_nM)
chk = pd.DataFrame({"IC50 (nM)": examples_nM, "pIC50 by hand": by_hand,
                    "pIC50 by code": by_code.round(3),
                    "agree": np.isclose(by_hand, by_code, atol=0.01)})
print(chk.to_string(index=False))
print("\nChEMBL's pChEMBL for the 41 nM EGFR record was 7.39; our 9 - log10(41) =", round(9 - np.log10(41), 2))

6. Fetching a target dataset from the ChEMBL web service

Now we assemble a real, target-specific dataset — the hands-on core of the unit. ChEMBL exposes a REST web service:[4] you build a URL with query parameters, ask for JSON, and read pages of results. The key parameters are the filter (target_chembl_id, standard_type), the field selector (only=..., to keep the payload small), the page size (limit, maximum 1000) and the page cursor (offset, followed via page_meta.next). For a computer scientist the mental model is comforting: a ChEMBL query is an ordinary HTTP GET whose query string is a dictionary of filters, and the response is JSON you parse into a dataframe. The service follows REST conventions, so the same URL always returns the same data (given a fixed release), results come back in pages of at most 1000, and the page_meta.next field is a cursor to the following page — you follow it in a loop until it is empty or you have collected enough rows, exactly as you would page through any paginated API. Two habits make a data pull a good citizen of a shared public service: ask only for the fields you need (the only= selector, which here cuts the payload to nine columns instead of the forty-odd a full activity record carries) and do not hammer the endpoint with rapid-fire requests — a handful of paged calls is fine, a tight loop of thousands is not. The chembl_webresource_client Python package wraps all of this in a friendlier interface, but we use plain urllib here so that the mechanics are visible and nothing needs installing beyond the standard library.

We request a single page of up to 1000 EGFR IC50 measurements. Every network call is wrapped so that a slow or blocked connection falls back to the bundled 30-compound sample, and the notebook always completes.

9. Linking to the target in 3-D: the Protein Data Bank

So far the target has been an identifier (CHEMBL203, UniProt P00533). The Protein Data Bank is where that target becomes a three-dimensional object, often with a ligand bound inside it. The glue that connects a ChEMBL target to a PDB structure is the UniProt accession. ChEMBL records that its target CHEMBL203 is the protein UniProt P00533; UniProt in turn lists every PDB structure solved for that protein; and each PDB entry records which small molecules (ligands) are bound in it. So the chain target → UniProt → PDB → ligand lets you move from "give me compounds measured against EGFR" (a ChEMBL question) to "show me a compound sitting in EGFR's binding site" (a PDB question) using one shared key. A data pull is not finished when the numbers are in memory; it is finished when it is reproducible and its licence is understood. Three obligations come with the territory. First, record the version: ChEMBL is released as dated, numbered snapshots, and a result that does not state which release it used cannot be reproduced — the cell above printed ours. Third, keep the query, not just the result, so the pull can be regenerated; this is the FAIR-data discipline[25] that separates a credible cheminformatics result from an irreproducible one,[26] and it is the professional habit behind the best practical guidance in the field.[27]

A common trap — "it's all IC50, so I can merge it"

The single most expensive beginner error in this unit is to pull every IC50 for a target and treat the numbers as interchangeable. They are not: they come from many assays (Figure 5, the assay table), in mixed units, some censored, with replicate scatter of up to a log unit. Merging them blindly produces a dataset that looks large and is quietly inconsistent — and a model trained on it will report a confident, wrong accuracy. The fix is the whole of Unit 7: harmonise units, resolve duplicates, handle censored values, and decide which assays may be combined.[24]

Bridge — to Unit 7 (curation)

The per_cpd table we just built is a raw dataset: real, reproducible, provenance-stamped, but not yet trustworthy. Unit 7 takes exactly this object and turns it into a modelling-ready set — harmonising units, resolving the duplicates and censored values we flagged, removing mixtures and inorganics, and documenting every record dropped. The data model you learned here (target → assay → activity) is what makes those curation decisions legible.

You should now be able to explain, without notes:

  • What ChEMBL, PubChem, the PDB, DrugBank, BindingDB and ZINC each store, roughly how big each is, and which identifier each assigns — and that you query a slice of the big ones rather than downloading them.
  • The identifier systems of chemistry: the difference between an assigned registry key (CAS, ChEMBL ID, CID, DrugBank ID) and a structure-derived key (canonical SMILES, InChIKey), and why the InChIKey is the de-duplication key of choice.
  • The bioactivity data model: a target has assays, an assay produces activities, and each activity joins one compound to one typed, united, possibly-censored value.

  • The pIC50/pChEMBL log transform, traced by hand, and why models are trained on it rather than on raw IC50.
  • How to assemble a target dataset from the ChEMBL REST service with a reproducible, offline-safe fetch, and how to read its unit mix, censored fraction and assay diversity.
  • Why a pull must record its database version and respect its licence, and what the raw per-compound table hands to the curation step of Unit 7.

12. Self-assessment

1. You want measured potencies for a protein target; your colleague wants to know which compounds are purchasable for a screen. Which database does each of you query, and why?You query ChEMBL (or BindingDB), which stores measured bioactivities linked to targets and assays. Your colleague queries ZINC, which catalogues purchasable / make-on-demand compounds but stores no activity data. They answer different questions: "what does this molecule do?" versus "which molecules can I obtain?".
2. Why can you download all of DrugBank into memory but not ChEMBL or PubChem?DrugBank is ~104 drug entries; ChEMBL is ~106 compounds with ~107 activities and PubChem ~108 compounds (Figure 1). The large resources are queried as slices through a web service; only the small ones are practical to hold whole.
3. What is the difference between a ChEMBL ID and an InChIKey as database keys, and which would you use to merge two compound lists from different sources?A ChEMBL ID is an assigned surrogate key, meaningful only inside ChEMBL; an InChIKey is a natural key computed from the molecular structure. To merge lists from different sources you use the InChIKey, because it is derived from the structure itself and will match the same molecule regardless of which database assigned which accession.
4. Two records produce InChIKeys that share the first 14-character block but differ in the second block. What does that tell you?They have the same molecular skeleton (atoms and bonds) but differ in a finer layer — typically stereochemistry (e.g. two enantiomers), or isotopes/protonation. They are constitutional equivalents but not identical molecules, so whether to treat them as "the same" depends on your curation policy.
5. Describe the path target → assay → activity → compound for the record we fetched (CHEMBL68920 at 41 nM).Target EGFR (CHEMBL203 / UniProt P00533) has an assay (CHEMBL674637, an EGFR-kinase phosphorylation inhibition assay); that assay produced an activity, an IC50 equal to 41 nM (pChEMBL 7.39), for the compound CHEMBL68920. The activity row is the join of all four plus the type/relation/value/unit.
6. IC50 and Ki are both potency measures in nM. Why is it riskier to merge IC50 values from different assays than to merge Ki values?IC50 is assay-dependent: it shifts with the substrate concentration used, so two labs measuring the same compound can report different IC50s purely from protocol differences. Ki (and Kd) are binding constants independent of substrate concentration, so they are more comparable across assays. The Cheng-Prusoff equation converts IC50 to Ki only if the assay conditions are known.
7. Compute the pIC50 of a compound with IC50 = 250 nM by hand.pIC50 = 9 - log10(250) = 9 - 2.398 = 6.60. (log10(250) = log10(2.5) + 2 ≈ 0.398 + 2.) So about 6.6 — a moderately potent compound.
8. Why do essentially all QSAR models train on pIC50/pChEMBL rather than raw IC50?Raw IC50 spans many orders of magnitude and is strongly right-skewed (Figure 4, left), which violates the assumptions of linear models and makes errors scale with magnitude. The log transform gives a roughly symmetric, bounded-range target (Figure 4, right) on which regression metrics and residuals behave sensibly.
9. In a raw ChEMBL pull you find 85 % of values in nM, 12 % in µM, and 3 % with relation '>'. What must you do before modelling?Convert the µM values to nM (or directly to pIC50) so all potencies are on one scale — never mix units. Handle the '>' (censored) values deliberately: they mean the true potency is weaker than a limit, so they cannot be used as exact numbers; drop them, cap them, or model them as censored. This is the start of Unit 7 curation.
10. The InChIKey PubChem returns for a compound equals the one you recompute with RDKit from PubChem's SMILES. What has this demonstrated?That two independent systems agree they hold the same molecule, verified through a structure-derived key rather than a shared registry. It confirms the SMILES round-tripped correctly and lets you confidently join the PubChem record (via its CID) to any other source that records the same InChIKey.
11. Why does the unit record the ChEMBL release version (e.g. ChEMBL_37) alongside the data?ChEMBL is published as dated, numbered snapshots that grow and change between releases. A dataset without its release version cannot be reproduced — a later ChEMBL would return different rows — so recording the version (and ideally the exact query) is a basic reproducibility and FAIR-data obligation.
12. A compound in your per-compound table has n_meas = 6 and a pIC50 spread of 1.3. Should you trust its potency, and what did we do about it?A spread of 1.3 log units (a factor of 20 in concentration) is large — larger than the typical ~0.5-log experimental noise — so no single value is trustworthy. We aggregated with the median, which is robust to such scatter, but the spread itself is a quality flag: it caps how accurate any model can be and would be scrutinised in Unit 7 curation.

Glossary

Activity (bioactivity)
A single measured number from an assay relating a compound to an effect on a target, with a type, relation, value and unit.
Assay
A reproducible laboratory experiment that measures what a compound does to a target or to cells; identified in ChEMBL by an assay ID.
CAS number
A registry number assigned by the Chemical Abstracts Service; an opaque surrogate key for a substance.
ChEMBL ID
An accession assigned by ChEMBL to a compound (CHEMBL...), assay or target.
CID
PubChem Compound IDentifier; PubChem's surrogate key for a unique chemical structure.
EC50 / IC50
The concentration producing half-maximal effect (EC50, stimulatory) or inhibition (IC50); assay-dependent potency measures. Lower = more potent.
InChIKey
A fixed-length (27-character) hash of the IUPAC InChI; a structure-derived natural key used to de-duplicate and cross-link compounds.
Ki / Kd
Inhibition and dissociation constants; true binding affinities independent of substrate concentration, unlike IC50.
pChEMBL / pIC50
−log10 of a molar potency; pIC50 = 9 − log10(IC50 in nM). Higher = more potent; the standard modelling target.
Potency
Informal term for how little compound is needed for an effect; captured quantitatively by IC50/Ki/EC50/pChEMBL.
PUG-REST
PubChem's REST web-service interface for programmatic access to compounds, properties and cross-references.
REST web service
A query interface where you build a URL with parameters and receive structured data (here JSON); how the large databases are accessed.
Target
The biological molecule (usually a protein) a compound is meant to act on; keyed by a ChEMBL target ID and a UniProt accession.
UniProt accession
The standard identifier for a protein sequence (e.g. P00533); the key that names a protein target across databases.
Censored value
A measurement reported only as above (>) or below (<) a limit, because the true value lies outside the assay's measurable range.
