1. What the toolkit is for

A thesis project in the group moves through five stages. It begins with a question that must be made quantitative — "is this scaffold more potent than that one?" becomes "is the median pActivity of the 30 compounds containing scaffold A greater than that of the 45 containing scaffold B, and how wide is the uncertainty on that difference?". It continues with data: a download from a public database, an output folder from a docking campaign, a trajectory from a simulation, a count matrix from a sequencing core. Then comes a model or a simulation, then validation, which is where most projects are won or lost, and finally a paper, in which every number must be traceable to a file and every figure to a script.

Python serves all five stages, which is the reason this laboratory runs on it. The scientific stack is a small set of libraries that interoperate because they all speak the same array language: NumPy provides the n-dimensional array and the numerical operations on it[1][2], SciPy the classical numerical algorithms[3], pandas the labelled table[4], Matplotlib[5] and seaborn[6] the figures, scikit-learn the machine-learning estimators[7]. Around that core sit the domain libraries the group depends on: RDKit for molecules[8], Biopython for sequences[9], MDAnalysis for trajectories[10]. Because they all accept and return NumPy arrays, a descriptor computed by RDKit can be scaled by scikit-learn and plotted by Matplotlib without a single conversion function written by you. That interoperability, not any individual library, is the thing worth learning. The interactive layer is IPython[11] and the Jupyter notebook[12], now the default working surface of data-intensive science[13]: an excellent laboratory bench and a poor warehouse, as Section 6 explains.

Domain context — what a bioactivity record is

The data file used in this unit is a table of bioactivity records. One record says: a particular compound (a small organic molecule, identified by a database code and by a text string that encodes its structure) was tested against a particular target (here the human enzyme ROCK1, a protein kinase studied in this laboratory for glaucoma and fibrosis indications[14]) in a particular assay (a laboratory experiment described in a publication), and the measured potency was a certain concentration. The concentration is usually an IC50 — the concentration of compound that halves the target's activity — or a Ki/Kd, which are binding constants. All three are concentrations, so smaller means more potent, and they span many orders of magnitude, which is why they are almost always analysed on a logarithmic scale (Section 5). The records in rock1_chembl_raw.csv were downloaded from ChEMBL[15], a public database that curates such measurements out of the medicinal-chemistry literature. For this unit that is all the chemistry you need: a record is a row, a compound is an identifier plus a structure string, and a potency is a positive number in nanomolar units whose logarithm is the quantity we model. One warning to carry forward: two laboratories measuring the same compound against the same target routinely disagree by half a log unit or more[16], so the numbers in this table are measurements, not constants of nature.

1.1 Environments: one per project, and why

An environment is an isolated directory containing a specific Python interpreter and a specific set of package versions. When you type import pandas, the interpreter searches that directory and no other. The point of one environment per project is that two projects can then disagree: a thesis finished last year keeps the pandas version its figures depend on, while today's project uses the current one.

  • conda / mamba (laboratory workstations; the way these notebooks are built). A project ships an environment.yml; conda env create -f environment.yml reproduces it and conda activate <name> enters it. This is the right choice when a project needs compiled scientific packages — RDKit, MDAnalysis, PyTables — because it ships binaries rather than compiling them.
  • uv / pip + virtualenv (pure-Python projects and web applications). A requirements.txt or pyproject.toml lists the packages, installed into a .venv directory inside the project.
  • Google Colab (for reading this course, and for anything a laptop cannot hold). Colab provides a disposable environment that already contains NumPy, pandas, SciPy, Matplotlib, seaborn and scikit-learn; extra packages are installed at the top of the notebook with a line such as !pip install rdkit. Every unit of this course has an "Open in Colab" button and a markdown note before the setup cell whenever an install line is needed.

The failure mode this prevents has a name in the literature: "it works on my machine" is not a communication problem, it is a data-integrity problem[17]. If a result depends on an unrecorded package version, the result is not a property of the data and the method; it is a property of a laptop.

2. Python aimed at data

Data work uses a narrow, recognisable subset of Python; this section is a refresher on that subset — the vocabulary the rest of the course writes in.

# The data-oriented Python subset: comprehensions, f-strings, pathlib, small typed functions.
raw_units = ["nM", "uM", "nM", "mM", "nM", "uM", None, "nM"]

# 1. List comprehension: build a list by transforming another one (the default loop of data work).
present = [u for u in raw_units if u is not None]

# 2. Dict comprehension: a frequency table, written as what it is rather than how it is built.
counts = {u: present.count(u) for u in sorted(set(present))}

# 3. A small function with type hints and a docstring: the unit of code that becomes src/ later.
TO_NANOMOLAR = {"nM": 1.0, "uM": 1e3, "mM": 1e6, "M": 1e9, "pM": 1e-3}

def to_nanomolar(value: float, unit: str) -> float:
    '''Convert a concentration to nanomolar. Raises KeyError for an unknown unit.'''
    return value * TO_NANOMOLAR[unit]

# 4. f-strings for readable output, pathlib for every filesystem operation.
here = Path(".").resolve()

Four constructs carry most data code. Comprehensions replace the accumulate-in-a-loop pattern. Small functions with type hints and a docstring are the atoms that later migrate into src/; the hints are not enforced at run time but they document intent. f-strings make output readable — note the :,.0f specifier that inserted the thousands separator above. pathlib replaces string concatenation for paths: Path("..") / "data" / name is correct on every operating system, whereas "../data/" + name is a bug waiting for a collaborator on another platform.

The fifth construct is error handling, and it deserves its own cell, because the single most common accident in data work is a conversion that fails silently on a value you did not know was in the column.

# Exceptions: fail loudly on bad input, and distinguish 'missing' from 'wrong'.
def to_nanomolar_safe(value, unit):
    '''Convert to nM; return (NaN, reason) for a missing or unrecognised input.'''
    if value is None or (isinstance(value, float) and np.isnan(value)):
        return np.nan, "missing value"
    try:
        return to_nanomolar(float(value), unit), "ok"
    except KeyError:
        return np.nan, f"unknown unit {unit!r}"
    except (TypeError, ValueError):
        return np.nan, f"non-numeric value {value!r}"

trials = [(25, "nM"), (2.5, "uM"), (1, "mM"), (10, "10'-8M"), ("n.d.", "nM"), (None, "nM")]
for v, u in trials:
    nm, status = to_nanomolar_safe(v, u)
    shown = f"{nm:,.0f}" if nm == nm else "NaN"
    print(f"{str(v):>6} {u:<8} -> {shown:>12} nM   {status}")

The table printed above is a conversion log, not just a result. The exotic unit string 10'-8M — which really occurs in the raw ChEMBL table of this course — and the text value n.d. were rejected with a reason, and the missing value was distinguished from the wrong ones. A bare except: is a bug

Writing try: ... except: pass catches everything, including the KeyboardInterrupt you press to stop a runaway cell and the MemoryError that explains why your results are wrong. Catch the specific exceptions you expect — KeyError, ValueError, FileNotFoundError — and let the rest reach you. The one legitimate broad catch in this course is the network call in Unit 3, where a failure of any kind must fall back to a frozen file; even there the exception type and message are printed rather than swallowed.

3. NumPy: the array is the unit of thought

NumPy's ndarray is a fixed-size block of memory plus three pieces of metadata: a dtype (how many bytes each element occupies and how to interpret them), a shape (the length along each dimension), and strides (how many bytes to step to move one element along each dimension)[1][2]. Everything that makes NumPy fast and everything that makes it surprising follows from those three facts. A Python list of a million floats is a million pointers to a million boxed objects scattered across memory; a NumPy array of a million floats is eight million contiguous bytes. The loop that adds one to each element therefore runs in compiled code over contiguous memory instead of in the interpreter over pointers.

# The ndarray model: dtype, shape, strides, memory, and views versus copies.
a = np.arange(12, dtype=np.int64).reshape(3, 4)
print("array:\n", a)
print("dtype", a.dtype, "| shape", a.shape, "| strides (bytes)", a.strides, "| itemsize", a.itemsize)
print("bytes held:", a.nbytes, "= 12 elements x 8 bytes")

b = a.astype(np.float32)
print("\nsame numbers as float32: nbytes", b.nbytes, "| itemsize", b.itemsize)

v = a[1]                      # a row is a VIEW: no copy, it shares memory with 'a'
v[0] = 999
print("\nafter writing into the view a[1], the parent array changed:\n", a)
print("view shares memory with parent:", np.shares_memory(a, v))
c = a[1].copy(); c[0] = -1
print("an explicit .copy() does not:", np.shares_memory(a, c))

Two lessons hide in that output. The first is arithmetic on memory: the same twelve numbers occupy 96 bytes as int64 and 48 as float32, and on ten million rows that factor decides whether an analysis fits in RAM. The second is the view: slicing does not copy, so writing into a slice writes into the parent — the 999 appeared in the parent because v and a describe one block of memory. The remedy is explicit: call .copy() when you intend a copy, and np.shares_memory when you need to know.

3.1 Vectorisation, measured

"Vectorise your loops" is advice everyone repeats and few have measured. Measure it now, on your own machine, because the size of the effect is the reason the whole scientific stack is built the way it is. The task is the one this course performs constantly: convert an array of concentrations in nanomolar to the logarithmic potency scale, $\mathrm{pActivity} = -\log_{10}(c\,[\mathrm{M}]) = 9 - \log_{10}(c\,[\mathrm{nM}])$.

# Loop versus vectorised, timed over four problem sizes. Each timing is the best of 3 repeats.
import math

def p_activity_loop(values_nm):
    out = []
    for v in values_nm:                      # interpreter-level loop over Python floats
        out.append(9.0 - math.log10(v))
    return out

def p_activity_vec(values_nm):
    return 9.0 - np.log10(values_nm)         # one compiled pass over contiguous memory

def best_of(func, arg, repeats=3):
    '''Best (smallest) wall-clock time of 'repeats' calls, in seconds.'''
    best = float("inf")
    for _ in range(repeats):
        t0 = time.perf_counter()
        func(arg)
        best = min(best, time.perf_counter() - t0)
    return best

sizes = [1_000, 10_000, 100_000, 1_000_000]
rows = []
for n in sizes:
    arr = rng.uniform(0.1, 1e5, size=n)      # concentrations in nM, seeded generator
    lst = arr.tolist()
    t_loop = best_of(p_activity_loop, lst)
    t_vec = best_of(p_activity_vec, arr)
    rows.append((n, t_loop, t_vec, t_loop / t_vec))
timing = pd.DataFrame(rows, columns=["n", "loop_s", "vector_s", "speed_up"])
print(timing.to_string(index=False, float_format=lambda x: f"{x:,.6f}"))
print("\nspeed-up at the largest size: about", f"{timing['speed_up'].iloc[-1]:.0f}", "times")

The lesson generalises beyond speed: a vectorised expression is also shorter, and shorter code has fewer places for an index error to hide. When you find yourself writing for i in range(len(df)), stop: there is almost always an expression for it.

When a loop is the right answer

Vectorisation has limits. A loop is correct and appropriate when each iteration is expensive and independent (fitting a model per compound, parsing a file per simulation replica), when the operation is genuinely sequential (a Markov chain, an iterative optimiser), or when the vectorised version would materialise an array that does not fit in memory. The rule is not "never loop"; it is "never loop over elements of an array to do arithmetic on them".

3.2 Broadcasting

Broadcasting is NumPy's rule for combining arrays of different shapes without copying them. Compare the shapes element by element from the right: two dimensions are compatible if they are equal, or if one of them is 1, in which case the array is treated as if that dimension were repeated. Nothing is actually repeated in memory — the stride for the broadcast dimension is simply set to zero — which is why broadcasting is both fast and memory-free.

# Broadcasting: centre and scale a small descriptor matrix, three ways, and check they agree.
X = np.array([[320.4, 3.1, 58.2],        # 4 compounds x 3 descriptors (MolWt, logP, TPSA)
              [455.9, 4.4, 74.1],
              [289.3, 2.2, 49.3],
              [512.6, 5.0, 96.5]])
col_mean = X.mean(axis=0)                 # shape (3,)
col_sd = X.std(axis=0, ddof=0)            # shape (3,)
print("X shape", X.shape, "| column means", np.round(col_mean, 2), "| column sds", np.round(col_sd, 2))

Z_broadcast = (X - col_mean) / col_sd                      # (4,3) with (3,) -> broadcast along rows
Z_explicit = (X - np.tile(col_mean, (4, 1))) / np.tile(col_sd, (4, 1))   # the same, materialised
Z_loop = np.empty_like(X)
for j in range(X.shape[1]):
    Z_loop[:, j] = (X[:, j] - col_mean[j]) / col_sd[j]

print("\nstandardised matrix (broadcast):\n", np.round(Z_broadcast, 3))
print("\nall three agree:", np.allclose(Z_broadcast, Z_explicit) and np.allclose(Z_broadcast, Z_loop))
print("column means after standardising:", np.round(Z_broadcast.mean(axis=0), 12))
print("column sds   after standardising:", np.round(Z_broadcast.std(axis=0), 12))

The three implementations give identical numbers, and only the first is worth writing. X - col_mean works because the shapes (4, 3) and (3,) align from the right: 3 matches 3, and the missing leading dimension is treated as 1 and broadcast to 4. The operation that pandas, scikit-learn and every modelling unit of this course performs on descriptor matrices — centring and scaling columns — is this one line. Note also the last two printed lines: after standardisation every column has mean 0 and standard deviation 1 to numerical precision, which is the definition of the z-score we will use from Unit 11 onwards.

Broadcasting is also the most common source of silent shape bugs, and the bug is worth producing deliberately once so that you recognise its signature: an array that is suddenly square.

# A failure mode worth producing on purpose: a column vector where a 1-D array was meant.
pred = np.array([6.1, 7.4, 5.2, 8.0])            # predicted pActivity, shape (4,)
obs_col = np.array([[6.0], [7.1], [5.5], [7.8]])  # observed, accidentally shape (4, 1)

wrong = pred - obs_col          # (4,) with (4,1) -> broadcast to (4,4). No error is raised.
right = pred - obs_col.ravel()  # (4,) with (4,)  -> elementwise, as intended

print("shapes:", pred.shape, obs_col.shape)
print("pred - obs_col   -> shape", wrong.shape, " (a 4x4 matrix of all pairwise differences!)")
print(np.round(wrong, 2))
print("\npred - obs_col.ravel() -> shape", right.shape, np.round(right, 2))

3.3 Random numbers that can be reproduced

Anything in this course that uses randomness — a train/test split, a bootstrap resample, the initialisation of a model, a permutation test — must be reproducible, because a reviewer or a colleague has to obtain your numbers. NumPy's modern interface is a generator object created with an explicit seed: rng = np.random.default_rng(0). Two generators created with the same seed emit the same stream; two created with different seeds do not. Pass the generator (or an integer random_state) explicitly into every function that needs randomness, rather than relying on a hidden global state.

# Seeds: same seed, same numbers; different seed, different numbers; and the global-state trap.

4. pandas: the labelled table

NumPy gives you a rectangle of numbers. Real data arrives as a rectangle of numbers and text, with named columns, missing entries and a meaningful row identity — in other words, as a table. pandas supplies two objects for that[4]: the Series, a one-dimensional array with an index, and the DataFrame, a dictionary of Series sharing one index. Everything else in pandas is an operation on those two.

The index is the part newcomers underestimate. It is not a row number; it is a label, and pandas aligns on labels automatically in arithmetic.

Chained assignment never writes where you think

5. A worked example by hand: from nanomolar to pActivity

Every unit of this course traces at least one calculation by hand and then confirms it by code, because a number produced with a pencil is a number you can debug. Here it is the conversion that every bioactivity table in the group passes through. A potency is reported as a concentration $c$, usually in nanomolar (nM, $10^{-9}$ mol/L); concentrations are multiplicative in nature — ten times more potent is a factor, not a difference — so the field works with the negative base-10 logarithm of the molar concentration:

$$\mathrm{pActivity} \;=\; -\log_{10}\!\big(c\,[\mathrm{M}]\big) \;=\; -\log_{10}\!\big(c\,[\mathrm{nM}] \times 10^{-9}\big) \;=\; 9 - \log_{10}\!\big(c\,[\mathrm{nM}]\big).$$

The last form is the one to memorise: subtract the log of the nanomolar value from 9. A larger pActivity means a more potent compound, and one unit of pActivity is one order of magnitude in concentration. Tracing four values by hand:

$c$ (nM) $\log_{10} c$ $9 - \log_{10} c$ pActivity
1 $\log_{10} 1 = 0$ $9 - 0$ 9.00
25 $\log_{10} 25 = \log_{10}(100/4) = 2 - 0.602 = 1.398$ $9 - 1.398$ 7.60
2 500 $\log_{10} 2500 = \log_{10}(10^4/4) = 4 - 0.602 = 3.398$ $9 - 3.398$ 5.60
100 000 $\log_{10} 10^5 = 5$ $9 - 5$ 4.00

The middle two rows use the one logarithm worth knowing by heart, $\log_{10} 4 \approx 0.602$ (because $\log_{10} 2 \approx 0.301$). Note the structure the table reveals: a hundred-fold change in concentration (25 nM to 2 500 nM) is exactly two units of pActivity, and the ratio of the two concentrations, not their difference, is what the scale preserves. The code below confirms all four values and then applies the same expression to the extract.

# Confirming the hand calculation, then applying it to the real column.

Why the logarithm is not optional

On the raw nanomolar scale, one compound at 0.5 nM and another at 1 nM differ by 0.5 units, while two inactive compounds at 50 000 and 100 000 nM differ by 50 000 — so an unweighted average, a least-squares fit or a Euclidean distance computed on raw concentrations is dominated entirely by the weakest compounds. On the pActivity scale both pairs differ by about 0.30 units, which is the chemically meaningful statement "a factor of two". Every statistical method in Blocks C and D assumes the modelling target is on a scale where distances mean something; for potencies, that scale is logarithmic.

6. Notebook discipline

A notebook has one property no script has: the order in which you ran the cells is invisible in the document. The saved file shows cells from top to bottom with their outputs, and nothing records that cell 12 was run before cell 7, that cell 9 was edited after it was executed, or that a variable was created in a cell you later deleted. This is hidden state, and it is the reason a large fraction of published notebooks cannot be re-executed: a study of 1.16 million notebooks on GitHub found that only a minority could be run top-to-bottom without error, and of those a smaller fraction reproduced the stored results[18]. The diagnosis is not carelessness; it is that the medium does not warn you.

The following cell makes the failure concrete by executing the same three "cells" in two different orders.

# Hidden state, demonstrated: the same three cells, two execution orders, two different answers.
cell_A = "threshold = 1000.0"                                  # the analyst sets a cut-off in nM
cell_B = "selected = work.loc[work['standard_value'] <= threshold]"   # ... and selects on it
cell_C = "threshold = 50.0"                                    # later, while exploring, the cut-off is changed

def run_order(order):

The discipline that removes the problem is mechanical and non-negotiable in this group.

  1. Restart and run all before saving, and before showing a result to anyone. If the notebook fails, the notebook is wrong, not the kernel.
  2. One concept per cell, and no cell that depends on a cell below it. A notebook should read as an argument, top to bottom.
  3. No hidden deletions. If you delete a cell that defined something, restart.
  4. Every cell's output is discussed. An output nobody reads is an output nobody checks.
  5. Parameters at the top. Thresholds, paths and seeds live in one cell near the beginning, never buried in the middle.
  6. Clear outputs before committing if they are large, but keep them if the notebook is the deliverable — as the pages of this course do.

These rules are the consensus of the "ten simple rules" literature for computational notebooks[19] and of the good-enough-practices guidance for scientific computing generally[17][20].

6.1 When a notebook becomes a script

A notebook stops being the right container at a predictable moment: when a piece of code is used twice. Three symptoms say the moment has arrived — you have copy-pasted a function from one notebook into another; a cell has grown past roughly fifty lines; or you want to test a piece of logic in isolation. The remedy is to move the function into src/, import it back, and leave the notebook to narrate the analysis.

8. Working with an AI coding assistant

AI coding assistants are part of the working environment, and pretending otherwise would make this unit obsolete on the day it was written. They are useful for the kind of code this course produces: a plotting idiom you have forgotten, a pandas reshape, a docstring, a first draft of a function whose logic you already know. They are also, measurably, a source of defects — an audit of assistant-generated code found that a substantial share of security-relevant completions contained vulnerabilities[21], the underlying models pass functional-correctness benchmarks only partially[22], and in scientific work the characteristic failure is not a crash but a plausible wrong number[23]. Scientific publishing has converged on a simple position: the tool is not an author and the human is accountable for every line[24].

This group's policy therefore has five steps, in order, and the middle three are not optional.

  1. Draft. Ask the assistant for a first version, with the context it needs (the dtypes, the shape, the units).
  2. Read. Read every line. If you cannot say what a line does, delete it or learn it — there is no third option.
  3. Test. Write the check yourself, on a case whose answer you know independently (by hand, from a published value, or from a degenerate case).
  4. Explain. Be able to explain the code to your supervisor without the assistant open. If you cannot, you do not own it.
  5. Attribute. Record in the project README that an assistant was used and for what. This is the same courtesy as citing a library.

The next cell shows why step 3 is the load-bearing one, using a draft that is wrong in the way assistants are characteristically wrong: fluent, well-formatted, documented, and off by a constant.

11. Self-assessment

Q1. A colleague sends you a notebook whose figures do not regenerate on your machine, although no cell raises an error. Name the three most likely causes, in the order you would check them.

(1) A different package version: check the printed environment cell — a changed default in pandas or Matplotlib silently changes output. (2) Hidden state in the original: the notebook was never restarted and run top-to-bottom, so a variable in the saved outputs was created by a cell that no longer exists; test by restarting and running all. (3) Unseeded randomness: a split or sample without random_state/seed gives different numbers every run. All three are diagnosed in minutes if the notebook prints its environment and seeds explicitly, which is why those two habits come first.

Q2. Why does a[1] on a NumPy array not copy the data, and when does this bite?

Because slicing produces a view: a new array object pointing at the same memory with different shape/stride metadata. It bites when you modify the slice intending to leave the original intact — the parent changes too. Use .copy() for an independent array and np.shares_memory(a, b) to check. pandas has the analogous distinction, which is why chained assignment is unreliable.

Q4. pred has shape (200,) and obs has shape (200, 1). What does pred - obs return, and what will an RMSE computed from it look like?

It returns a (200, 200) matrix of all pairwise differences, silently, because broadcasting aligns the shapes from the right and expands both. The RMSE computed from it is a plausible-looking number, typically inflated (in the cell above, roughly double the correct value), with no error raised. Guard with assert pred.shape == obs.shape.

Q5. Explain why np.random.default_rng(0) called twice in a cell gives the same numbers, while calling .normal() twice on one generator does not.

A generator is a deterministic function of its internal state; the seed sets that state. Two generators created with the same seed start from the same state and therefore emit the same stream. A single generator advances its state with every draw, so consecutive calls return different numbers — which is what you want for independent replicates. Re-seeding inside a loop destroys that independence and is a common bug in bootstrap code.

Q6. df[df["x"] > 0]["y"] = 1 runs without error and changes nothing. Why, and what is the correct form?

The expression selects a subset (a new object), then assigns into that temporary, which is discarded; the original table never sees the write. Under pandas 3's copy-on-write semantics this is consistent rather than occasionally lucky. The correct form is a single indexing operation: df.loc[df["x"] > 0, "y"] = 1.

Q7. When should a text column be converted to category, and when does the conversion cost rather than save memory?

Convert when the number of distinct values is small relative to the number of rows (a rule of thumb: below a few per cent), as for assay type or units. Do not convert when nearly every value is distinct — a SMILES or an identifier column — because a category then stores the full dictionary plus an integer code per row, using more memory than the strings alone. Check with nunique() before converting, and remember to pass observed=True to groupby afterwards.

Q8. An IC50 is reported as 250 nM. Compute the pActivity by hand, then state what a pActivity of 8.0 corresponds to in nanomolar.

pActivity $= 9 - \log_{10} 250 = 9 - 2.398 = 6.60$. Conversely, pActivity 8.0 means $\log_{10} c\,[\mathrm{nM}] = 1$, i.e. 10 nM. Useful anchors to memorise: 1 nM = 9, 10 nM = 8, 100 nM = 7, 1 µM = 6, 10 µM = 5.

Q9. Your notebook selects records below a threshold, and the threshold is defined in a cell below the selection. The notebook shows a sensible result. Is it correct?

Unknowable from the document, which is the problem. If the cells were executed in the order shown, the selection would have raised NameError; since it did not, they were executed out of order, so the stored output used a threshold that the top-to-bottom reading does not produce. Restart and run all: whatever comes out is the only defensible result. Move all parameters to one cell near the top.

Q10. Why does raw data live in a folder that code is forbidden to write to, when a checksum would detect an accidental change anyway?

A checksum detects the change afterwards; the convention prevents it. The deeper reason is that every derived file must be regenerable from the raw data by running code — the test of reproducibility is "delete data/processed/, results/ and figures/, run one command, get them back". If code may edit the raw folder, the chain from source to result is broken and the test is meaningless.

Q11. An assistant drafts a function and it passes your anchor test. What are the remaining two steps of the policy, and why is "it passes the test" insufficient?

Explain and attribute. A test checks the cases you thought of; it says nothing about the cases you did not — here, negative or zero concentrations, missing values, arrays versus scalars, or units other than nanomolar. Being able to explain the function is what lets you predict where it breaks; attribution is what lets a reader of your thesis judge the artefact as it was actually made.

Glossary

Bioactivity record
One measurement of one compound against one target in one assay, with a value, a unit and a relation symbol.
Broadcasting
NumPy's rule for combining arrays of different shapes by comparing dimensions from the right; a dimension of length 1 is treated as repeated, at zero memory cost.
Categorical dtype
A pandas column type that stores each distinct string once plus one small integer code per row; cheap for low-cardinality text.
Censored measurement
A value reported with > or < rather than =; the true value lies beyond the tested range.
Chained assignment
Writing through two consecutive indexing operations (df[mask]["col"] = x); it modifies a temporary and leaves the original unchanged.
DataFrame
A pandas table: a dictionary of Series sharing one index.
dtype
The element type of an array or column — how many bytes each element uses and how they are interpreted.
Environment
An isolated interpreter plus a fixed set of package versions; one per project.
Hidden state
Variables or results in a notebook that depend on an execution order the saved document does not record.
IC50 / Ki / Kd
Concentration-scale potency measurements; smaller means more potent. IC50 is the concentration halving a target's activity; Ki and Kd are binding constants.
Index (pandas)
The row labels of a Series or DataFrame; arithmetic aligns on labels, taking the union of indices. loc selects by label, iloc by position; never substitute one for the other.
ndarray
NumPy's n-dimensional array: contiguous memory plus dtype, shape and strides.
pActivity
$-\log_{10}$ of a potency expressed in molar; equals $9 - \log_{10}(c\,[\mathrm{nM}])$. One unit is one order of magnitude.
Restart-and-run-all
Clearing the kernel and executing every cell in order; the only way to know what a notebook actually computes.
Rule of two
Code used a second time moves from the notebook to src/.
Seed
The integer that fixes a random generator's initial state, making a stochastic computation reproducible.
Series
A one-dimensional pandas array with an index and a dtype.
Split-apply-combine
Grouping rows by a key, reducing each group, and assembling the results; groupby(...).agg(...) in pandas, GROUP BY in SQL.
Strides
The byte steps needed to move one element along each dimension of an array; what makes views possible.
Vectorisation
Expressing an elementwise computation as one array operation executed in compiled code rather than as an interpreter loop.
View
An array sharing memory with another; writing into it writes into the parent.
